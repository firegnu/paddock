## 现在是怎样（主控 10-19 对着代码核对的）
- 窗格的目录（`view.rs` 的 `directory`）：shell 窗格是开 shell 时的目录，不跟着 `cd` 变；agent 窗格是 agent 的 `cwd`；`Launch::Command` 是它的 `cwd`。P5-143b 认相对路径按它解析，所以 `cd` 之后 ⌘ 点相对路径会找错地方或打不开。
- shell 不一定告诉终端自己在哪：OSC 7（`file://主机/路径`）zsh、bash 默认都不发（macOS 只在 Terminal.app 里由 `/etc/zshrc_Apple_Terminal` 发）；vte 不处理 OSC 7，paddock 也没接。
- paddock 已经在看 shell 的子进程（`pty.rs` 的 `running_programs`，用 `libc` 读进程组和进程名），本机能用 `proc_pidinfo` 一类的接口读到一个进程的当前目录。
- 新开 shell（⌘T、分屏）一律用 `NewShell.cwd`：paddock 启动时的目录（`main.rs`）。

## 要做的（用户 10-19 定）
1. **shell 窗格的当前目录**：读本机 shell 进程的当前目录（不认 OSC 7：vte 不处理它，要自己从输出里挑；zsh、bash 默认也不发）。⌘ 点相对路径时按这个目录解析（P5-143b 的 `directory`／`place`）。读目录不能卡界面线程（照 P5-143b：查文件在界面线程外）。
2. **从 shell 窗格新开 shell**：当前窗格是本机 shell 时，⌘T、分屏新开的 shell 落在它的当前目录；当前窗格是 agent、空窗格、远程窗格时照旧用 `NewShell.cwd`。目录已经不存在时退回 `NewShell.cwd`。
3. agent 窗格、远程窗格、`Launch::Command`：照旧，不变。

## 完成记录（主控 10-19）

**做了什么**
- `pty.rs`：shell 会话（`spawn_shell` 起的，含 agent shell）在读 PTY 输出的线程里，每读到一段输出就用 `proc_pidinfo(PROC_PIDVNODEPATHINFO)` 读一次 shell 进程的当前目录，存起来；`Session::current_dir()` 取这个值（不是 shell、或已在结束的会话为 `None`）。界面线程只读存好的值，不做系统调用。
- `viewer.rs` `shell_dir()`、`view.rs` `shell_dir()`：正在跑的本机 shell 的当前目录；还在排队的 shell、agent、`Launch::Command` 都是 `None`。
- `view.rs` `directory()`：先用 shell 的当前目录，没有（shell 还没输出过）再退回开 shell 时的目录；agent、命令窗格照旧。⌘ 点相对路径（P5-143b 的 `place`）因此按 `cd` 之后的目录解析。
- `window.rs`：新标签页（`new_shell` 开新标签那一支）和 New tab／Split 面板里选 Shell、Agent shell 时，用当前窗格 shell 的目录；当前窗格不是本机 shell、或目录已不在（`is_dir` 为假）时退回 `NewShell.cwd`。空窗格里开 shell、关掉最后一个标签后自动补的 shell、恢复布局时的 shell 照旧用 `NewShell.cwd`。

**验证了什么**
- 先红后绿：`pty::tests::a_shell_tells_the_directory_it_has_gone_to`（zsh `-f -i` 起在临时目录，`cd` 到别处、再 `cd /`，读到的目录跟着变）、`viewer::tests::a_running_shell_is_where_it_has_gone_to`、`window::tests::a_shell_opened_from_a_shell_starts_where_that_one_is_while_it_is_there`（目录在、不在、没有三种），三条先跑红（读不到目录／总是退回），实现后转绿。`pty::tests::what_a_pane_attaches_to_is_not_a_shell` 加了一条：不是 shell 的会话没有目录。
- `view::links::tests::a_shell_s_relative_paths_are_from_where_it_has_gone_to`：shell `cd` 到另一个目录后屏幕上写的 `src/main.rs` 按新目录找到文件，按开 shell 时的目录找不到。这条是实现后写的，它依赖的 `current_dir` 已先红过。
- 三项检查：`cargo test --all-targets` 865 过 0 失败；`cargo clippy --all-targets -- -D warnings` 无警告；`cargo fmt --check` 过。

**拿主意的地方**
- 在读输出的线程里读目录，不在界面线程、也不另起定时器：shell `cd` 之后一定会打印提示符，所以读到的总是新的；没输出时不做任何事（P5-143a 省 CPU 不丢）。代价是大量输出时每 4 KB 一次系统调用（微秒级）。
- Agent shell 也算 shell，从 shell 窗格开 Agent shell 同样跟着目录。
- 读到的是系统给的真实路径：在 `/var/...` 里会显示成 `/private/var/...`，不影响打开文件。
- 新开 shell 时 `is_dir` 在界面线程上查一次（只在用户开 shell 那一下，和起 shell 本身相比可忽略）。
