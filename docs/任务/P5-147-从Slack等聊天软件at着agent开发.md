# 任务：Settings 里显示 Slack 机器人的状态（从聊天软件 @ agent 开发，主体在 ranch）

依据：用户 10-19：“再加一个draft task，可以接入slack等社交软件，通过社交软件AT的方式进行交互开发”。10-20、10-21 和主控谈定了做法和范围（见「已定的」）；10-21：“验收照这七条。先把任务书写好。暂时先别排。”10-21 用户又问“P5-147这个任务整体是不是可以移到ranch中的任务队列中”，选了主控建议的“主体移 ranch，留 Settings”：机器人交给 ranch 建任务，本件只剩 paddock 的 Settings 那块。
依赖：R38
优先：低

## 现在知道的（主控 10-19 对着本机命令和代码说的）
- 和 agent 往来的公开命令已经够用：`corral send` 发话，`corral wait` 等一轮结束，`corral reply` 取这一轮的回复，`corral status`、`corral ls` 看状态，`corral start` 开新的。聊天软件那头只要把这几条接上，原则上不用改 agent。
- paddock 的收件箱（铃铛那块，P5-87，`app/src/inbox.rs`）就是在做类似的事：读每个主控的最新回复，在里面直接回话，不用去它的窗格。Slack 这条可以看成把收件箱搬到聊天软件里。
- 难的地方：
  - 安全：聊天软件里的消息会变成 agent 的指令，谁能 @、能 @ 哪些 agent、能不能开新 agent，都要定。
  - 运行位置：要有一个一直在跑、连着聊天软件的程序（机器人）。
  - 回复长度：agent 的回复可能很长，带代码块，需要裁剪或换个形式。
  - 机器人的凭证不能进公开仓库。

## 已定的（用户 10-20、10-21）
- **架构照 ranch 接 agent 的做法，做成插件**（用户 10-20：“这个架构要设计一下，我觉得应该像ranch接不同agent那样的设计，类似插件的形式”）：每家聊天软件一个适配器（连接方式、凭证、@ 的写法、有没有线程、消息长度和格式），登记在一张表里；共用核心不写任何一家的名字，管 @ 谁对应哪个 agent、权限、聊天线程和 agent 对话的对应、长回复裁剪、提醒；和 agent 只走 corral 公开命令（send、wait、reply、status、ls）。凭证放本机，不进仓库。
- **放进 ranch**（用户 10-20：“接受你的建议，甲”）：和 corral 一样是每台机器一份、一直在后台跑的运行时，不开 paddock 也能用；paddock 只在 Settings 里显示它的状态和配置，读它的 JSON 输出。实现在 ranch 仓库里照 ranch 的规矩做，本仓库这件只管 paddock 这边和把需求写清楚交给 ranch。
- **分两期**（用户 10-20：“同意，分两期”）：第一期：@ 已经在跑的 agent 说话（送过去、等这一轮结束、回复贴回同一线程，线程里接着回就是接着聊）；Needs you 和主控新回复在固定频道提醒，点进线程直接回（收件箱搬到聊天软件里）；看状态（哪些在干活、哪些在等）。第二期：在聊天里开、停 agent。
- **怎么 @ 到 agent：一个频道对应一个仓库**（用户 10-21 选了主控建议的这一种，备选是“只一个频道、每条写全名”和“和机器人私聊”）。平台只能 @ 真实用户或机器人，所以只有一个机器人。
  - 频道在配置里绑一个仓库；频道里 `@机器人 说话` 默认送给这个仓库的主控（`<仓库>/main`）。
  - 第一个词是同仓库某个 agent 的短名，就送给它；跨仓库写全名（`ranch/main`），只能送给绑了频道的仓库。
  - 线程里回复不用再 @，送给线程开头那个 agent；一个线程就是和这个 agent 的一段对话。
  - 机器人先回一行 `→ <agent 全名>`，送错了一眼看得出；写了带斜杠的全名但没有这个 agent 时报错，不转给主控。
  - Needs you 和主控新回复发到 agent 仓库对应的频道；在提醒的线程里回复，送给这个 agent。
- **没绑频道的仓库一个字都不发到 Slack**（用户 10-21 选了主控建议的这种，备选是保留总频道配白名单、照原样全发；改掉了上一条原先“没绑频道的发到一个总频道”）。起因：“只有用户能发话”管的是谁能指挥 agent，管不到哪些内容会发出去；有总频道的话，本机所有仓库，包括私有的工作项目，都会把代码、路径、报错发到 Slack 的服务器上，工作区管理员也看得到。
  - 没有总频道；提醒、回复、看状态都只涉及绑了频道的仓库。
  - 跨仓库写全名指向没绑频道的仓库时，机器人只回“这个仓库没接入 Slack”，不送、不转。
  - 是否接入按仓库逐个决定，默认不接入；要接入就给它绑一个频道。
  - 绑了频道的仓库，回复原样整段发出去，第一期不做内容过滤；绑频道就等于接受这个仓库的内容进 Slack。
- **先接 Slack**（用户 10-21 选了主控建议的这家，备选是飞书、Discord、Telegram）。理由：线程完整，对得上“一个线程一段对话”；Socket Mode 由机器人往外连，本机不需要公网地址。
- **第一期只有用户自己能用**（用户 10-21 选了主控建议的这种，备选是白名单里的几个人、按人分权限）：机器人只接受配置里列出的那个用户 ID，同频道里别人的消息一律不理。
- **第一期只在这台 Mac 上开**（用户 10-21 选了主控建议的这种，备选是交给 ranch 设计多机）：只管本机的 agent；别的机器（如 5090）装了 ranch 也默认关着。起因：两台机器用同一个 Slack 机器人连上去，Slack 会把每条消息随机交给其中一条连接，话可能落到没有这个 agent 的机器上。管远程 agent 以后另行设计。

## 这一件做什么
- 只做第一期的 paddock 这一半：Settings 里显示 ranch 的 Slack 机器人连没连上、绑了哪些频道。只读 ranch 给的命令和 JSON，不读 ranch 的配置文件和凭证。放哪一页、长什么样，开工时先出样子给用户看。
- 机器人本身（下面验收 1–6）10-21 交给 ranch，在 ranch 仓库照 ranch 的规矩做，paddock 不改 ranch。ranch 建成 R38（ranch `docs/任务/R38-从Slack等聊天软件at着agent开发.md`，ranch main `8cc2fe5`，优先低、不开工）；给 paddock 的只读命令和 JSON 等 R38 做完写进 ranch `docs/CONTRACT.md`，ranch/main 会通知。
- 开工顺序：ranch 那件做完、部署、把命令和 JSON 写进它的 `docs/CONTRACT.md` → 再开本件的 worktree，照 CONTRACT 做。第二期（在聊天里开、停 agent）以后另开。
- 现在不排（用户 10-21：“暂时先别排”）：worktree 没建，等 ranch 那件做完、用户说开始。

## 交给 ranch 的需求（10-21 送给 `ranch/main`，请它记进队列、优先低、不开工）
连同上面「已定的」和用户原话一起送。
- **要什么**：跟着 ranch 装在每台机器上、开了就在后台一直跑的程序（第一期只在一台上开，见「开在哪」），连着聊天软件：把用户在聊天里说的话送给 agent，把这一轮的回复、Needs you 和主控新回复送回聊天里；能在聊天里看哪些 agent 在干活、哪些在等。不开 paddock 也能用。第一家接 Slack。
- **结构**：插件式，照 ranch 接不同 agent 的做法：每家聊天软件一个适配器，登记在一张表里；共用核心不写任何一家的名字。
- **和 agent 往来**：只走 corral 公开命令（send、wait、reply、status、ls）。第一期不开、不停 agent。
- **送给谁、发到哪**：照「已定的」里「怎么 @ 到 agent」和「没绑频道的仓库一个字都不发」两条。仓库就是 agent 全名斜杠前那段。
- **谁能用**：只接受配置里的一个用户 ID，别人的消息一律不理。
- **开在哪**：第一期只在用户这台 Mac 上开，只管本机 agent；别的机器装了 ranch 也默认关着（原因见「已定的」）。
- **凭证**：只放本机，不进任何仓库，也不出现在给 paddock 的输出里。
- **给 paddock 的**：一条只读命令，输出 JSON，至少有：在不在跑、连没连上（连不上时的原因）、绑了哪些频道各对应哪个仓库。写进 ranch `docs/CONTRACT.md`。
- **交给 ranch 定的**：命令名、配置文件的位置和格式；Slack 怎么接、要哪些权限；后台怎么常驻；长回复怎么分段（不能悄悄截掉）；agent 正在干活时又来了话怎么办（要在线程里告诉用户）；怎么判断“主控新回复”和 Needs you、怎么不重复提醒；机器人重启后线程和 agent 的对应还在不在。

## 验收
用户 10-21：“验收照这七条。”本件只管第 7 条；1–6 是机器人本身的，跟着需求交给了 ranch。
1. 在 `#paddock` 里 @bot 说一句，`paddock/main` 能收到，这一轮的回复贴回同一个线程；在线程里接着回，就是接着和它聊。
2. 某个 agent 变成 Needs you，或者主控有新回复时，对应频道里出现提醒；在提醒的线程里回复，能送到这个 agent。
3. 在聊天里能看哪些 agent 在干活、哪些在等。
4. 没绑频道的仓库，提醒、回复、状态都不出现在 Slack；跨仓库 @ 它会被拒绝。
5. 别人在频道里 @bot，机器人不理。
6. Slack 的凭证只放在本机，不进任何仓库。
7. paddock 的 Settings 里能看到它连没连上、绑了哪些频道。
