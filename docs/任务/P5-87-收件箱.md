**左边：名单（约 290 宽，样稿 1）**
- 三组，没有内容的组不画：
  - `Needs you`：等待中、出错的 agent 和 corral 读不出来，不管是不是主控都列，排法和现在一样。
  - `New replies`：有新回复没读的主控（`role=controller` 标签）。
  - `Read`：其余的主控（读过的、正在干活的、暂停的）。
- 不是主控的 agent 只在等待或出错时出现；它们的新回复不进名单。
- 每行：名字、项目、图标、时间照现在名单的画法，下面多一行——有回复的写回复的第一句（去掉 Markdown 记号，一行放不下省略），等待和出错的写原因，正在干活的写 `Working`。
- 点一行是选中它、在右边显示，不再直接跳到窗格。
- 弹层开着的时候行不换组：读过、回过的仍留在原来的组里（圆点和文字变淡）；新来的回复照常加进 `New replies`。关掉再开，按当时的状态重排。
- 打开时选中第一行。

**右边：原文（样稿 1）**
- 顶行：agent 全名、状态小标（`New reply`、`Waiting for input`、`Error`、`Working`；读过的空闲 agent 不画小标）、多久之前、`Open pane` 按钮。
- 中间：这个 agent 最后一条回复的原文，按 Markdown 排，长了可以滚，每次换选中的行都从头显示。
- `Open pane`：关掉弹层，照现在点一行的做法把那个 agent 的窗格带到前面。
- 没有回复可显示（还没有过、或读不出来）：用一句英文说明，`Open pane` 照常能点。

**读过**
- 一条回复在右边显示出来就算读过：从 `unread` 里去掉，铃铛的数字、左侧栏卡片和标签胶囊上的记号跟着变。

**回复框（样稿 1）**
- 多行输入框，占位文字 `Reply to <全名>…`。↩ 发送，⇧↩ 换行；输入法正在选字时的 ↩ 归输入法，不发送。框随内容长高，长到几行为止你拿主意。
- 只有这个 agent 是空闲的才能回。正在干活：框换成一句 `Working… you can reply when this turn ends`，Send 灰掉（样稿 3）。暂停、等待、出错的同样不能回，说明文字对得上状态。
- 发送：空白的不发。在后台调 `corral send <全名> <文字>`，文字原样作为一个参数（多行、引号都不改），不在画界面的线程里等。不加 `--force`、`--after`。
- 发送中 Send 写 `Sending…`，框不能改。
- 发出去之后（样稿 3）：框清空；原文下面多一块 `You · sent just now` 和发的那句；刚才那条回复留着、变淡；立即催一次 corral 的读取，让状态尽快变成 `Working`。停在这一行，不自动跳到下一条。它的下一条回复出来后，右边换成新回复，`You` 那一块撤掉。
- 被拒绝或失败：文字留在框里，框下面用琥珀色写原因：
  - `not_idle`：`It's busy — try again when this turn ends`
  - `human_active`（30 秒内刚在它的窗格里打过字）：`You typed in its pane a moment ago — try again shortly`
  - agent 已经不在：`It's no longer running`
  - 别的：corral 给的那句话。
- 没发的字留着：切到别的行再切回来还在，关掉弹层再开也还在；只留在内存里，退出 paddock 就没了。

**弹着提问的 agent（样稿 2）**

- corral 读不出来那一行：右边只写错误原因，没有 `Open pane`，不能回。

## 怎么算做完
- 用户原话：“我的注意力主要是来回在各个主控之间切看消息。”——不切窗格，在一个地方就能读到各主控最后一条回复的原文，并且就地回一句。“看起来还是不错的”——样子和样稿 1、2、3 一致，上面「要做的」逐条达到。
- 先写测试、确认它因为功能还没有而失败，再实现。下面五样各有测试即可，不做覆盖矩阵；涉及 corral 的一律用假 corral 脚本：

  - 能不能回：空闲能回，干活、暂停、等待、出错不能回，各自说的话。
  - 送话：假 corral 收到的正是 `send`、全名和原样的文字（含换行和引号），没有 `--force`；`not_idle`、`human_active`、不在了、别的失败各写出对应的那句，文字留着。
