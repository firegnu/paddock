## 要做的（照「用户 10-20 已定的」和样稿）
1. **切换加 `History`**：`Uncommitted｜Branch vs main｜History`，和前两项同一种画法。选 History 时不读工作区改动，读提交历史；切回去照旧。
2. **读历史**：只用 git 的只读命令，从 `HEAD` 往下读当前分支的历史（含合并进来的分支上的提交，按 `git log --graph` 那样排），不读别的本地分支和远端分支。先 200 条，列表滚到底再读下一批。标签显示时和现在一样按时重读，有新提交出现在最上面，已选中的提交保持选中，滚动位置不跳。后台读法照搬 Changes 现有的（线程、取消标记、只在标签显示时读）。
3. **提交图**：每行左边一列画线：主线一条竖线，合并进来的分支在旁边一条线，从合并提交分出、在分叉点并回主线；提交是线上的小圆点，选中的那行圆点实心、整行淡强调色底。线的颜色：主线一种、分支一种，都用现有主题色（不加新的颜色键）。同时开着几条分支线时依次往右排。
4. **一行写什么**：上面一行提交说明（一行，太长省略）；说明里有任务编号时，编号放在前面一个小号等宽的小胶囊里（样稿那样），剩下的说明跟在后面；下面一行淡色：短 hash（等宽）· 作者 · 多久以前，合并提交多写 `· merge`。收尾提交（说明以 `收尾:` 开头）整行变淡。
5. **点一行**：下面（窄面板）或右边（拉宽到 `WIDE` 以上）显示这次提交的 diff，用现有的 diff 画法（文件索引、每个文件的 diff、窄面板 unified、拉宽可 Split）。上面先一段：完整提交说明、短 hash、作者、时间、改了几个文件和增删行数。合并提交对第一个父提交比；收尾这类空提交写一句 `No changes in this commit.`。窄面板里提交列表和 diff 之间一条可拖的分隔，默认列表占上面四成左右。
6. **悬停按钮**：一行悬停时右端出 `Copy hash`（复制完整 hash 到剪贴板）；说明里认得出任务编号、`docs/任务/` 里正好有一份这个编号的文件时，再多一个 `Open task`（用系统默认程序打开那份文件，同看板的 `Open task file`）。编号怎么认：去掉开头的 `合并`、`收尾:`、`任务:` 这类前缀后，开头的编号，沿用 `kanban.rs` 认编号的办法（`task_id` 的规则），不另写一套。
7. **空状态**：不在 git 仓库里、或者仓库还没有提交时，和 Uncommitted 现在的空状态同一种写法。
