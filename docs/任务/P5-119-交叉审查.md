### 1. 必须改：保存入口之后的外部修改会被覆盖，备份也救不回来

- 位置：`app/src/instructions.rs:174–185`（`save`）、`app/src/instructions.rs:235–243`（`replace`）。
- 问题：只在 `save` 入口读取并比较一次；随后备份、写临时文件、`sync_all`，最后直接 `rename` 覆盖目标。另一个编辑器在这段时间里更新文件，保存仍返回成功，备份却是第一次读取的旧内容，外部更新会从目标和备份两处一起消失。界面上的三次比较挡不住这个保存函数内部的时间窗口。违反任务「要做的」第 5 条的外部修改保护，属于保存丢数据。
- 复现：在 `/tmp` 自建目录中，从受审文件原样抽取 `save`、`keep`、`replace` 等相关函数编译一次小型 Rust 程序。用 16 MiB 的合成旧文本放大备份耗时，另一个线程等备份文件出现后，用 `rename` 把内容为 `external update` 的合成文件放到目标位置。实际结果：`save` 返回 `Ok`，目标只有 `my edit`，备份只有旧文本，外部更新丢失。复现未接触真实指令文件。
- 改法：备份和临时文件准备好后，必须重新校验实际将被替换的文件；发现内容变化则返回 `Changed`，保留草稿。最终替换也应保留实际被移走的旧文件并校验它，发生竞争时安全恢复或保留并明确告知位置，不能直接覆盖后丢弃它。可参考仓库 `app/src/skills_files.rs` 中固定目录、保留被移走对象、校验后再完成操作的思路；这里仍需满足整份替换及软链接保留要求，不能仅把同一次入口检查挪到别处就宣称解决。

### 2. 必须改：编辑时缓存的目标路径会漏掉软链接变化，甚至覆盖链接本身

- 位置：`app/src/settings_instructions.rs:94–100、148–150、207、236`；`app/src/instructions.rs:174–184、243`。
- 问题：`Edit` 只记开始编辑时的 `file.target`，回到前台、进入对比、保存都检查这个旧路径，没有从 agent 的主文件路径重新解析。
  - 若主文件的链接从 A 改为内容不同的 B，旧 A 没变，三处比较都认为没冲突；保存写 A 并报告成功，agent 实际读的 B 不受影响。回到前台时 `files` 又已读成 B，卡头甚至会显示 B，实际仍写 A。
  - 若开始编辑时是普通文件，期间被移走并在原处建立指向它的软链接（内容相同），入口比较通过，最后 `rename` 把软链接本身替换成普通文件，真正的链接目标没有得到编辑内容。
- 复现：同一次 `/tmp` Rust 程序按界面流程保存 `read(...).target`，分别进行上面两种路径变化。两次 `save` 都返回 `Ok`；第一种确认写的是旧 A，第二种确认主路径已经不是软链接。这不是需要抢在两个系统调用之间才能出现的竞争，变化完全发生在用户编辑期间即可。违反第 5 条的外部修改保护和「链接本身不动」。
- 改法：编辑状态保留 agent 的主路径以及打开时解析到的目标；三处检查及实际保存都从主路径重新解析。目标关系变化时进入冲突流程，要求 `Reload` 后再编辑，不能静默沿用旧目标；最终写入只针对重新核对过的实际普通文件，并与第 1 条的替换保护一起防止临近写入时换链。

### 3. 建议改：备份和临时文件的初始权限会放宽原文件的访问范围

- 位置：`app/src/instructions.rs:189–209、235–242`。
- 问题：两处 `OpenOptions` 都没指定创建权限。原文件即使是 `0600`，在常见 umask `022` 下备份仍会是 `0644`；临时文件也先以默认权限写入全文、同步之后才改成原权限。同一次合成文件复现实际得到「原文件 `600`，备份 `644`」。最终主文件的 mode 确实保留了，但副本没有同样的保护。
- 改法：备份及临时文件创建时就设为仅用户可读写（例如 Unix `OpenOptionsExt::mode(0o600)`），临时文件写完后再按要求恢复原文件权限。新建的备份目录也可只对当前用户开放，不要顺带更改用户已有目录的权限。本条属于额外的副本隐私保护建议，按本次分级约定不列合并阻塞。

### 4. 建议改：关闭 Settings 会无提示丢掉 Instructions 草稿

- 位置：`app/src/settings_instructions.rs:23、26–40`，`app/src/settings_view.rs:1134–1143`；系统关闭回调在 `app/src/windows.rs:118–120`。
- 问题：新页的草稿只存在 `Edit` 中，Settings 的关闭路径只调用原有配置提交逻辑然后销毁窗口；没有保存 Instructions，也没有提示。正在编辑、对比或保存失败后按关闭／⌘W 都会丢掉这份草稿。开发完成记录已经如实披露，但原来设置页立即保存的理由不能覆盖这个新增的显式保存页面。
- 改法：仅在 Instructions 有未保存改动时提供放弃／继续编辑的关闭处理，或者保留草稿到再次打开；不要绕过 Review 自动写全局文件。这是体验建议，不是本任务新增验收条件，按约定不挡合并。
