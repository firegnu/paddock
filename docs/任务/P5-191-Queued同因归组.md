## 要做的
1. **哪些算一组**（写成纯函数，给它单测）：同时满足才归一组：
   - 在 Queued 里（草稿也算），且不在 Loop 框里（即 `listed(Queued)` 列出来的那些）；
   - 有 `待用户：` 的内容（`Card::asks` 非空）；只因 agent 在等而标 Needs you、没有文字的不参加；
   - 文字相同：比较前去掉首尾空白、连续空白当一个空格，此外一字不差（全角半角标点不同就不算同一组）；
   - 至少 2 件。只有 1 件的照现在两行的样子画。
2. **组放在哪**：Queued 原有的顺序（P5-60a：优先级、草稿、编号）不变；一组放在它排得最前的成员的位置，成员按原顺序紧跟着放在组里，其余任务的先后不变。
3. **组头**（照样稿甲）：在 Queued 的框里占一条，淡琥珀底、琥珀细边、圆角：折叠箭头、粗体琥珀 `Needs you`、理由（一行，放不下由 paddock 量宽度截、加 `…`，悬停写全文，同现在 `asks` 的做法）、琥珀件数小签。整条可点，点一下展开或收起。
   - 收着时（默认）：组头下面一行淡色小字，按组里的顺序列成员标题，用 ` · ` 隔开，放不下截断加 `…`（样稿里用的是顿号，这里改成不分语言的 ` · `）。
   - 展开时：成员一件一行：圈、编号、标题（一行，放不下截断），行尾依次是依赖（链接符号加编号）、`Draft`／`High`／`Low` 小标、格式警告。不再画每件自己的 Needs you 一行和 Waits for 一行。
4. **展开或收起不记住**：默认收着；按理由文字记哪些组展开了，只在这次运行里有效，重启回到收着（同 DONE 的 `Show all`）。理由文字变了就算新的一组，收着。
5. **成员行的操作照旧**：悬停出现的按钮（Open task file、Clear、Set priority、Edit、Drop task 等）和就地确认，跟现在每张卡一样，确认那一行出现在这件下面。Clear 只清这一件；清完剩不到 2 件，组就散掉，剩下那件回到两行的样子。组头上不放“全部清掉”这类按钮。
6. **Queued 整个收起时**：照 P5-29b 仍列出 Needs you 的任务，用同样的归组画法（组照它自己的展开或收起状态画）。
7. **加宽后的五列**：Queued 那一列用同样的归组规则和组头；展开后成员一件一行（编号、标题），宽度不够就截断标题。
8. 不变的：顶部的 `N need you` 计数、Loop 框和它的 Next、别的栏、圈的样子、DONE 里 Needs you 的画法。界面文字是英文。
