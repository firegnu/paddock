### R2｜必须改：运行目录检查后可被祖先路径替换，bind 落入非私有目录

- **位置**：`app/src/control.rs:133-165`、`487-493`；客户端 `299-311` 也使用先检查路径、再按路径连接的方式。
- **问题**：`runtime_dir` 只 canonicalize 一次并检查 base／paddock 末级目录，随后保存的是路径字符串，没有约束可改名的祖先目录，也没有固定已核验的目录身份。如果配置的私有 base 位于可由其他主体改名的父目录中，在最后一次目录检查后把 base 改名、原位置换成指向另一目录的链接，`UnixListener::bind` 会跟随新路径。`chmod` 只把 socket 设为 0600，不会纠正或拒绝实际的非私有父目录。
- **验证**：一次性 Rust 程序通过 `#[path]` 直接加载审查 worktree 原始 `control.rs`，调用未经改写的 `Server::start()`；仅对本探针不会调用的 Browser 地址补全提供桩。临时夹具先有 0700 的 base／paddock，并发线程把 base 换成通往 0777 替代目录的链接。实测启动成功，socket 实际位于 **0777** 目录，socket 自身为 0600，且能响应 `instances`。探针全部在当前 UID 的临时目录里模拟换路径，**没有把这次结果声称为已实测跨 UID 连接**；判为必须改的依据是任务第 1 条要求的实际运行目录 0700／不符合时拒绝已被绕过。
