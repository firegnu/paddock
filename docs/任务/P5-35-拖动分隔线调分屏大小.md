## 要做的
用户 10-07 同意主控建议的“拖动分隔线调分屏大小”。
1. **比例**：每个分叉记一个比例（第一块占的份额），新分屏仍是对半。比例随布局保存、重启后恢复；旧布局文件没有比例时当作对半。
2. **拖动**：鼠标移到两个窗格之间的缝上，光标变成左右（或上下）调整光标，缝上出现一条细的强调色线；按住拖动实时改比例，松开结束。嵌套分屏各拖各的。
3. **双击缝**：恢复对半。
4. **最小尺寸**：任何一块都不能被拖到小于大约 20 列宽、5 行高（按当前字体换算）；窗口变小时按比例缩，不出现负尺寸。
5. **终端跟着变**：拖动中终端按新大小重排（可以节流），松开后行列数正确。
6. **Browser**：拖动期间 Browser 的原生网页视图照 `browser::cover()` 的统一规则隐藏，松开后恢复，不出现网页盖在缝上或跟不上的情况。
7. 只从主题取色，不新增主题颜色键；尊重“减弱动态效果”（如果加了过渡动画）。

## 完成记录

- 做了什么：`layout.rs` 的 `Node::Split` 加 `ratio`（第一块的份额，新分屏仍是 `EVEN` 对半，关窗格时别的分叉保留比例）；一个分叉用“缝后第一个窗格”来指认，`Workspace::set_ratio`／`even` 只改当前标签里那一个分叉；`clamp_ratio` 和 `Node::least` 算夹取（嵌套时按同方向窗格数累加最小尺寸，两块都放不下时按最小尺寸的比例分，不出负数）。`layout_state.rs` 的 `SavedNode::Split` 存 `ratio`，旧文件没有时按 0.5，读入时要求在 0 和 1 之间（不含），否则照旧把整份布局当坏文件保留不覆盖；版本号不变。`window.rs`：两块之间的 8pt 缝变成一个真元素（左右分屏是左右调整光标，上下分屏是上下调整光标），悬停或拖动时缝中间亮一条 3pt 的 `agents_accent` 线；两块用 `flex_grow` 按比例分；按下时从 `spots`（沿用已有的“记下画在哪里”机制，加 `Spot::Seam`）取分叉的长度，拖动实时改比例，松开存布局；双击缝恢复对半并保存。拖动时 `dragging` 为真：盖住整个窗口、光标保持，Browser 网页照 `cover()`／`place(dragging)` 的统一规则隐藏，松开恢复。
- 验证了什么：新测试 `moving_a_nested_seam_changes_only_its_split`、`a_double_click_splits_in_half_again`、`seams_stop_at_each_parts_least_size`、`split_ratios_are_saved_and_older_files_split_in_half`，`broken_layouts_are_refused` 加了越界比例；`app/` 下 `cargo test --all-targets`（335 个通过）、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check` 都过。release 程序用 `PADDOCK_NO_ACTIVATE=1`、临时 HOME／`XDG_CONFIG_HOME`／`XDG_STATE_HOME`、假 corral、预写 `ratio: 0.68` 的左右分屏布局启动，只截自己的窗口，看过：两张卡片约 68:32，重启后布局文件里比例仍是 0.68。截图在 scratchpad，未入库。
