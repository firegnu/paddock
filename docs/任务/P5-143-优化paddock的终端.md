# 任务：优化 paddock 的终端

依据：用户 10-19 问了 paddock 的终端怎么来的，主控讲了三层做法；用户：“所以说理论上我能把这个terminal做的更炫”，主控答可以，列了能做和难做的；用户随后：“再加一个drft task，优化一下paddock下的terminal”。主控建议分三批（先修底层、再做链接、最后平滑滚动和光标），用户：“按你的顺序写进P5-143吧”。用户又说：“我理解这个是一个非常独立的任务，就是terminal这边的修改，不牵涉任何和agent相关的东西”。

## 现在是怎样（主控 10-19 对着代码核对的）
- 三层：`portable-pty` 开伪终端（`app/src/pty.rs`）；`alacritty_terminal` 解析输出成格子、回答终端查询（`app/src/terminal.rs`）；paddock 自己用 GPUI 画格子、收键盘鼠标（`app/src/view.rs`、`view/`、`app/src/input.rs`）。前两层和输入编码从 Saddle `df1c727` 迁来，画的那层是 paddock 新写的。
- 路线（DESIGN §2）：“GPUI＋alacritty_terminal 自己画”，以 Zed 内置终端为参照；暂不完整嵌入 Ghostty。Zed 的终端代码是 GPL，只参考思路。
- 还在的缺口：每个窗格每 8 毫秒查一次有没有新输出（`view.rs:250`）；程序问颜色时答 xterm 默认色（`terminal.rs:67` 的 `default_rgb`），不是主题调色板；写入通道容量 64（`pty.rs:83`），极大粘贴可能被拒；滚动按行跳（`view.rs` `scroll_wheel`）；光标不闪、移动没有过渡；输出里的网址、路径不能点。

## 范围：分三批，按顺序做（用户 10-19 同意的顺序）
只改终端这一层：`pty.rs`、`terminal.rs`、`view.rs`、`view/`、`input.rs`，以及终端用到的设置项。不碰 agent、corral、侧栏、卡片、看板。agent 窗格里跑的也是这个终端，所以改好后那里显示也跟着变，但不改任何和 agent 有关的逻辑。
每批开工时另写一份任务文件（`P5-143a`／`b`／`c`），写清做法、验收，给用户看过再动手；本文件是总的。

### 第一批 P5-143a：底层三处
1. 有新输出才唤醒重画，不再每 8 毫秒轮询；没输出的窗格不占 CPU。
2. 程序查询颜色（OSC 4／10／11／12 等）时答当前主题的终端调色板、前景、背景、光标色；换主题后再问答新的。
3. 大段粘贴不被拒：写入通道满了要排队写完，不丢、不报 busy。

### 第二批 P5-143b：网址和文件路径能点
- 输出里的网址、文件路径（含 `路径:行号`）认出来；按住 ⌘ 悬停加下划线、指针变手，⌘ 点击打开：网址在右侧栏 Browser 打开，文件路径的打开方式开工时和用户定（Changes、编辑器或别的）。
- 程序用 OSC 8 明确标出的链接也照样能点。
- 不按住 ⌘ 时，点击和选择照旧，不误触。

### 第三批 P5-143c：平滑滚动和光标
- 回看历史按像素平滑滚动（触控板、滚轮都顺），全屏程序（vim、less 等）里的滚动行为不变。
- 光标移动时滑过去（可带一点拖尾），闪烁渐隐渐显；程序要求的光标形状、隐藏照旧。
- 程序用 OSC 12 设了光标颜色时，画光标也用它设的颜色（P5-143a 只让查询答它设的值、画照旧用主题色；用户 10-19 同意留到这一批：“光标留到P5-143c”）。
- 先出样稿或小原型给用户看手感，再定细节（速度、拖尾长短、要不要开关）。

### 以后再说（这次不做）
选区和查找高亮的圆角半透明、字体连字和按窗格字号；终端里显示图片、自定义着色器效果（主控不建议，投入大、风险高）。

## 怎么算做完
- 用户原话：“按你的顺序写进P5-143吧”。
- 主控建议的验收（待用户确认，每批任务文件里再细化）：
  1. 第一批：开着十个没输出的窗格时 paddock 的 CPU 明显低于改前；在 nvim 等会查背景色的程序里，配色跟着 paddock 主题走；粘贴几 MB 文本完整进去。
  2. 第二批：终端输出里的网址、路径能 ⌘ 点击打开；普通点击和选择不受影响。
  3. 第三批：用户实际用触控板滚动、看光标移动，觉得顺；样稿或原型先经用户点头。
  4. 每批照规矩跑三项检查、写完成记录；键盘、触控板、观感留给用户实际体验。
