### R1【必须改】另一套替身目录可使一次性调用无限回到自身

- 位置：`app/src/agent_shell.rs:113–150`（`clean_path`、`find_program` 和放行分支）。
- 问题：清理只排除 `PADDOCK_AGENT_SHIMS` 指定的目录及其目录别名；`find_program` 只检查候选是否为可执行文件，不检查它是否仍然指向 paddock。本实现按进程生成不同替身目录，PATH 一旦残留另一套替身目录，当前替身就会把另一套的 `claude` 当成真程序。放行分支保留原 `PADDOCK_AGENT_SHIMS`，下一次执行仍找到同一个替身，形成连续 `exec`，连 `claude --version` 都不能返回。托管分支也可能把另一个替身的绝对路径交给 corral，而非真正的 agent。这未达到验收中的“一次性放行”和“找真程序跳过替身目录”。
- 复现：在临时 HOME 下建 `first`、`second`、`real` 三个目录；前两者的 `claude` 都链接到本次编译的 paddock，`real/claude` 是退出码 23 的合成 sh 程序。清空继承环境后，以 `PADDOCK_AGENT_SHIMS=first`、`PATH=first:real` 调用 `first/claude --version`，正常退出 23；只把 PATH 改为 `first:second:real`，3 秒后仍未退出，审查辅助程序结束并回收了自己记录 PID 的子进程。源码也能确认循环：第一次去掉 first 后，后续每次仍选中 second，PATH 不再变化。没有启动窗口或真实 agent。
- 改法：查找真程序时排除仍指向 paddock 的替身，至少按解析后的可执行文件路径／文件标识识别自身；传给真程序和 `--env PATH` 的路径也应去掉识别出的其他替身目录。补一个“两套独立替身目录＋真程序”的回归，证明放行确实执行真程序、托管参数也传真程序的绝对路径。

### S1【建议改】启动失败时遗漏 corral 的具体错误原因

- 位置：`app/src/agent_shell.rs:317–321`；对应夹具 `app/tests/agent_shell.rs:217–220`。
- 问题：目前只取 JSON 的 `error`。公开 corral 实现的错误格式是 `{"ok":false,"error":"错误码","message":"具体原因"}`（只读核对 ranch 源码 `crates/corral/src/lib.rs` 的 `Error::new`，未读取运行时状态或用户配置）。因而真实失败通常只显示 `exec_failed`／`usage`，看不到具体原因；现有测试把原因直接放进 `error`，没有覆盖实际格式。
- 复现：临时假 corral 返回合成 `exec_failed` 和独立 `message`，经 PTY 运行本次替身，退出非 0，输出含错误码而不含合成原因。返回 shell 的主行为仍正常，故不挡合并。
- 改法：读取并展示 `message`，同时保留错误码；合并后的诊断仍走环境值遮盖，不能直接打印整个 JSON 或 argv。夹具改用真实协议形状。

### S2【建议改】区分未设置与显式空值的 ZDOTDIR

- 位置：`app/src/agent_shell.rs:60–64,75`。
- 问题：`original_zdotdir.unwrap_or_default()` 把 `None` 和 `Some("")` 合为一类，`${PADDOCK_AGENT_ZDOTDIR:-$HOME}` 又把空值改成 HOME，因此并非所有“原来设了 ZDOTDIR”的情况都能还原。用户显式导出空值时，会额外加载 HOME 下的启动文件。
- 复现：全部使用临时 HOME、合成 `.zshenv`／`.zshrc` 和本次源码中的包装文本。普通 `/bin/zsh -i -c ...` 在 `ZDOTDIR=""` 下不加载这两份 HOME 文件；包装后两份均被加载。常见的未设、非空自定义目录已由现有 PTY 测试通过，这个边角不列必须改。
- 改法：独立保存“原变量是否存在”，按存在性恢复；确实未设置时再按任务规定退回 HOME。补空值与未设置的区别检查。
