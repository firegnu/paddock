## 现状（10-09 调查）
- 问不问只看 `window.rs` 的 `question()`：凡是活着的 shell（`shell_live()`：启动中、运行中、排队中）都算，交给 `close_question()`。用到它的：⌘Q 和主窗口的关闭按钮（`windows.rs` 的 `quit` → `confirm_quit`）、关窗格、关标签（`request_close`）。
- P5-47 起窗口里几乎总有 shell，所以 ⌘Q 几乎每次都弹。
- `paddock ctl close` 走自己的一套（`control_ui.rs`，`--confirm-shells` 加确认码），不经过 `question()`。
- 判断办法实测过（临时小程序，已删）：`portable-pty` 的 `process_group_leader()`（`tcgetpgrp`）给出终端的前台进程组，和 shell 的进程号比，不同就是前台有程序；程序名用 macOS 的 `proc_name`；管道取第一个程序。后台任务（`cmd &`）是 shell 的直接子进程、有自己的进程组，前台仍是 shell。用户本机的 zsh（powerlevel10k）停在提示符时底下没有子进程（gitstatusd 挂在另一个脱离出去的 zsh 下），所以“有子进程”可以当作“有后台任务”。

## 要做的
1. `pty::Session` 加“shell 里在跑什么”：shell 还在时，前台进程组不是 shell 自己就给出前台程序名，再加上 shell 的其余直接子进程（后台任务，和前台同一进程组的不重复算）的名字；停在提示符时为空。取不到名字时写 `a program`。`pty.rs` 文件头改为注明本仓库改过。
2. `question()` 只收里面有程序在跑的 shell；停在提示符、还在启动、排队中的 shell 不问，直接关或退出。
3. 确认框每行写“窗格标题 — 程序名”（如 `shell · ~/paddock — cargo`），标题和说明改成在说这些程序（英文）。
4. ⌘Q、关窗口、关窗格、关标签一起按新规则。

## 不做
- `paddock ctl close` 不改（用户同意主控建议：它给 agent 用，关用户的 shell 前先问更稳妥）。
- 不设忽略单：`less`、`top` 等在前台也问。
- 程序坞菜单“退出”、注销仍由系统直接结束（GPUI 没有拦截）。

## 完成记录

- 做了什么：`pty::Session::running_programs()`：shell 还在时，前台进程组（`process_group_leader()`，即 `tcgetpgrp`）不是 shell 自己就算一个任务；再用 macOS 的 `proc_listchildpids` 找 shell 的直接子进程，按进程组（`getpgid`）归并，和 shell 同一进程组的（提示符之类的帮手）不算；每个任务用组长的名字（`proc_name`，组长先退出时用子进程的名字，都取不到写 `a program`），重名只写一次。`viewer.rs`、`view.rs` 各加 `shell_programs()` 传上去（排队中的 shell 为空）。`window.rs` 的 `question()` 只收有程序在跑的 shell，每行由新的 `shell_line()` 写成“标题 — 程序, 程序”；`close_question()` 的文案改为 “Quit paddock and end what runs in the shell(s)?”／“End what runs in the shell(s)?”，说明改为列表加 “The shell closes too.”／“The shells close too.”，按钮不变（Quit、End Shell(s)）。`pty.rs` 文件头注明本仓库改过。DESIGN §13 加 P5-66 条。
- 验证了什么：先写测试再实现，两处都先看到因缺功能而失败（`running_programs` 空壳时认不出 `sleep`；旧文案和新断言对不上）。新测试：用真 pty 起 `zsh -f -i`，提示符时为空，前台 `sleep 30` 时是 `["sleep"]`，Ctrl-C 后回到空，`sleep 31 &` 后台时是 `["sleep"]`，`kill %1` 后回到空；`corral attach` 那样的非 shell 会话为空；`close_question` 两项改成新文案和“标题 — 程序”。pty 测试连跑 5 次都过。开工前另用临时小程序在用户真实的 zsh 配置（powerlevel10k）下核对过：停在提示符时 shell 没有子进程（gitstatusd 挂在另一个脱离出去的 zsh 下），所以不会因为它每次都问。`app/` 下 `cargo test --all-targets`（454 项全过）、`cargo clippy --all-targets -- -D warnings`、`cargo fmt --check`、`git diff --check` 都过。
- 拿主意的地方：和 shell 同一进程组的子进程不算，免得提示符里跑的命令（如取 git 状态）恰好在退出那一刻被算进去；代价是关掉作业控制的 shell 里的后台任务认不出来（交互 shell 默认开着作业控制）。`&!` 脱离的任务也会被算进去、照样问（认不出它已脱离），多问一次无害。
- 没做的事：真窗口里 ⌘Q、关窗格、关标签的感受留给用户（主控不模拟按键）。`paddock ctl close` 按约定没改。
