## 现状（10-09 调查）
- 问不问只看 `window.rs` 的 `question()`：凡是活着的 shell（`shell_live()`：启动中、运行中、排队中）都算，交给 `close_question()`。用到它的：⌘Q 和主窗口的关闭按钮（`windows.rs` 的 `quit` → `confirm_quit`）、关窗格、关标签（`request_close`）。
- P5-47 起窗口里几乎总有 shell，所以 ⌘Q 几乎每次都弹。
- `paddock ctl close` 走自己的一套（`control_ui.rs`，`--confirm-shells` 加确认码），不经过 `question()`。
- 判断办法实测过（临时小程序，已删）：`portable-pty` 的 `process_group_leader()`（`tcgetpgrp`）给出终端的前台进程组，和 shell 的进程号比，不同就是前台有程序；程序名用 macOS 的 `proc_name`；管道取第一个程序。后台任务（`cmd &`）是 shell 的直接子进程、有自己的进程组，前台仍是 shell。用户本机的 zsh（powerlevel10k）停在提示符时底下没有子进程（gitstatusd 挂在另一个脱离出去的 zsh 下），所以“有子进程”可以当作“有后台任务”。

## 要做的
1. `pty::Session` 加“shell 里在跑什么”：shell 还在时，前台进程组不是 shell 自己就给出前台程序名，再加上 shell 的其余直接子进程（后台任务，和前台同一进程组的不重复算）的名字；停在提示符时为空。取不到名字时写 `a program`。`pty.rs` 文件头改为注明本仓库改过。
2. `question()` 只收里面有程序在跑的 shell；停在提示符、还在启动、排队中的 shell 不问，直接关或退出。
3. 确认框每行写“窗格标题 — 程序名”（如 `shell · ~/paddock — cargo`），标题和说明改成在说这些程序（英文）。
4. ⌘Q、关窗口、关窗格、关标签一起按新规则。

## 不做
- `paddock ctl close` 不改（用户同意主控建议：它给 agent 用，关用户的 shell 前先问更稳妥）。
- 不设忽略单：`less`、`top` 等在前台也问。
- 程序坞菜单“退出”、注销仍由系统直接结束（GPUI 没有拦截）。
