# 任务：看板第一次打开某个仓库时慢：任务文件一次读完

依据：用户 10-15：“现在第一次打开某一个agent对应的kanban的时候有点慢。看看解决方案，顺便看一下cairn那个panel是不是也存在这个问题”。
执行：主控

## 在哪里干活
- worktree：`../paddock-worktrees/p5-112-kanban-batch`，分支 `p5-112-kanban-batch`（已从 main 建好）。

## 查到的（主控 10-15，用 paddock 自己的读取代码在本机实测）
- 看板读一个仓库（`kanban::read`）时，main 上每个任务文件各跑一次 `git cat-file blob <oid>`，读过的按 blob 记在缓存里。缓存跟着 paddock 进程，所以每个仓库只有第一次打开时要全读。
- 每条命令除了 git 本身约 6ms，paddock 的命令执行（`command::run_bounded`）每 10ms 才看一次进程结束没有，一条约 15ms。
- 实测：
  - paddock（main 上 178 个任务文件）：第一次 2.47 秒，之后每次 0.12 秒。
  - ranch：第一次 0.27 秒，之后 0.10 秒；cairn 仓库：第一次 0.32 秒，之后 0.11 秒。
  - 同样 178 个 blob，逐个 `cat-file` 在终端里约 1.0 秒，一条 `git cat-file --batch` 读完约 0.02 秒。
- Cairn 面板没有这个问题：一次读（`cairn status`、`show --json`、`list --json --limit 200`、两条 git）约 0.15 秒，每次都差不多，跟仓库大小和第一次无关。

## 要做的
1. 没在缓存里的任务文件，用一条 `git cat-file --batch` 一次读完（把 blob id 从标准输入送进去，按 `<oid> blob <size>` 的头切开）；读回来的照旧进缓存。缺的（`<oid> missing`）和别的失败照旧算 `Read::Failed`。
2. 命令执行加一个能送标准输入的入口（现在只有 `Stdio::null()`）：照现有的 `git::git` 选项（`--no-lazy-fetch` 等、不继承 `GIT_*`）、超时和取消；写标准输入放在单独的线程，不和读输出互相卡住。
3. 未合并任务读分支上任务文件那一处（每件开着的活一次 `ls-tree` 加读 blob）数量少，照旧，blob 也走缓存。
4. 测试：多个任务文件第一次读出来和逐个读的结果一样；缓存里有的不再读；有一个 blob 缺失时整次读算失败；标准输入的入口有超时和取消。用临时仓库，不碰真实仓库。
5. 自查照 AGENTS.md「合并前」，再用同样的办法实测 paddock 仓库第一次读的时间，写进完成记录；合并后重新打包安装。

## 怎么算做完
- 用户原话：“现在第一次打开某一个agent对应的kanban的时候有点慢。看看解决方案”。
- 主控提议、用户同意（“可以，开始吧”）：paddock 仓库看板第一次读从 2.5 秒降到 0.3 秒以内（照上面的实测办法量）。

## 不做
- 不改每 10ms 看一次进程结束的做法（影响所有命令，省下的每条约 5ms，单独再说）。
- Cairn 面板不用改。
- 不改看板的显示和规则。
