## 要做的
用户原话：“在左侧的agents面板中能否有一个类似github那种提交的那种展示的格格展示，可以在settings的上方占一点空间。要酷炫一点的。”看过三种样稿和主控的推荐后：“按照你的建议来吧。先做出来。这块我觉得可以做的酷炫一点”。

1. **位置**：左侧栏 agent 列表下面、底部设置图标那一行上面，一块圆角小面板（样稿 A）。列表照旧能滚动，格子图不随列表滚动。侧栏收起成窄条时不显示。
2. **格子**：7 行（一周七天），每列一周，最右一列是本周，今天之后的格子留空；列数按侧栏当前宽度能放几列放几列，拖宽侧栏就多显示几周。月份标在上方。每格的深浅＝当天的提交数，分 5 档（0 档是底色），只用主题色（`agents_accent` 加透明度之类）。
3. **数据**：
   - 仓库列表：左侧栏看到的每个 agent，取它目录所在 git 仓库的主仓库（worktree 也归到主仓库），记进状态目录里的一份小文件（和 `layout.json` 同目录，名字你定），只记仓库路径，不记其他任何东西；以后 agent 关了，仓库也保留在列表里。仓库路径已不存在的跳过。
   - 每天的提交数：对列表里每个仓库现读 git（只读命令，经 `git::git`），统计所有本地分支上的提交（同一个提交只算一次），按提交的作者时间、本机时区落到哪一天。只统计格子图显示得到的那些天。
   - 当天收尾了几件：main 上首行是 `收尾: <编号>` 的提交数（`kanban::wrapped_id`）。
   - 在后台读，不卡界面；定时刷新（间隔你定，分钟级即可），仓库列表变了也刷新；结果没变不重画。
4. **酷炫**（样稿是底线，可以在这些规矩里做得更好，做了什么写进完成记录）：
   - 第一次显示时格子依次弹出（样稿是沿对角线）；之后刷新不再整片重播。
   - 今天那格有一圈会“呼吸”的光。
   - 悬停某格：浮出一张小卡片，写日期、提交数、按仓库分的提交数（最多列三四个，其余合并）、当天收尾了几件。
   - 顶部一行：`ACTIVITY`、总提交数、周数；底部一行：连续有提交的天数、Less→More 图例。
   - 开了“减弱动态效果”时一律不动：没有弹出、没有呼吸，直接显示最终样子。
5. **折叠**：点面板的标题行可以折叠成一行（例如 `ACTIVITY · 29 today · 12-day streak`），再点展开；折叠状态随布局保存。
6. **样子**：只从主题取色、可加透明度，不新增主题颜色键；三套预置主题、界面字号 13 和 18、磨砂开关两种下都好看；数字用等宽字体。没有仓库、或都没有提交时，格子照样画（全是底色），标题行写 `No activity yet`。界面文字英文。

**拿主意的地方**
- 深浅按显示范围里最忙那天四等分（1–¼、¼–½、½–¾、¾–满），但最忙那天不到 8 条时按 8 算，免得一天一条就画成最深。
- 连续天数：今天还没提交时从昨天往回数（今天没结束不算断）。一周从周日开始，和 GitHub、样稿一致。月份名标在周日落入新月的那一列，相邻至少隔三列，最后两列不标（放不下）。
- 只读显示得到的天：用 `--max-age`（按提交者时间）提前两天截断，再按作者时间精确落天。代价：若有人手工把某个提交的提交者时间设得比窗口早、又压在新提交上面，git 会在那里停下，下面的不算；正常提交、rebase、cherry-pick 都不受影响。
- 仓库列表里路径不在的读时跳过，下次写文件时就不再写进去；多个窗口各自读写时先合并文件里已有的，不互相覆盖。某个仓库 git 读失败按 0 算，不让整轮作废。
- 刷新间隔 60 秒；corral 列表变化、侧栏宽度变化（周数变）、过了午夜都会立即重读。
- 今天那格的呼吸限 15 帧/秒：它一直在动，而窗口里的终端不是缓存视图，每一帧都会整窗重画；呼吸慢（2.4 秒一次），15 帧看不出卡。
