## 现在是怎样（主控 10-19 对着代码核对的）
- 拖选：`view.rs` 的 `mouse_down`／`mouse_move`／`window_move`／`window_up`，状态在 `view/press.rs` 的 `Mouse`。拖出窗格时 `locate` → `grid::cell_at` 把位置夹到最上或最下一行，所以选区停在边上那一行，不会滚。
- 滚动：P5-143c2 后回看历史按像素（`view/glide.rs`：`Glide::drag` 立即走、`Glide::wheel` 缓动），整行由 alacritty 的 `display_offset` 管；Settings 的 `Smooth scrolling` 关掉时按行滚。
- 拖着不动时没有鼠标事件：要靠定时器或每帧继续滚。

## 要做的
1. 拖选时鼠标在格子区域上边之外：视野往更早的历史滚；下边之外：往更新的滚（到底停）。离边越远滚得越快（有上限）；鼠标回到格子区域里就停。
2. 鼠标拖着不动也一直滚，选区的一端跟着滚进来的那一行走，松开就停。
3. 用平滑滚动的那套（`Smooth scrolling` 开时按像素走，关时按行走）；滚到顶或底停住。
4. 只在拖选时滚：程序要了鼠标、按着 ⌘ 点链接（`Press::Link`）、全屏程序（alt screen，没有历史）时不滚；左右拖出窗格照旧，不滚。
5. 不在拖时不留定时器、不要帧（P5-143a、c1、c2 的省 CPU 不能丢）；窗口失去前台或按下被取消时立即停。

## 完成记录（主控 10-19）

**做了什么**
- 新文件 `view/edge.rs`：拖选越过上下边时怎么滚，只用普通数字，方便测试。上边外往更早的历史滚，下边外往更新的滚；离边越远越快。每帧按距上次的时间走（一帧最多按 50 ms 算，窗口被挡住后回来不会一下跳很远）。`Smooth scrolling` 开着时交给 `Glide::drag` 按像素走，关着时攒够一整行才走一行；到顶、到底、回到格子里就停。
- `view.rs`：窗口级的鼠标移动（`window_move`）里判断要不要开始或继续滚（`follow_edge`）：只在拖选时、不是全屏程序、鼠标在窗格上边以上或下边以下时滚，左右拖出照旧。滚动放在 `build` 里一帧一帧做，同时把选区的一端放到鼠标所在那一行（贴边那一行）；还要滚就 `request_animation_frame`，不滚就不要帧、不留定时器。松开（窗格里、窗格外）、窗口失去前台、程序进了全屏，都立即停。
- `view/press.rs`：加 `Mouse::selecting()`（只有拖选和从链接拖成的选区算，报给程序的按下、⌘ 按在链接上不算）。`window_up` 遇到普通拖选也结束它：窗格只听得到自己上面的事件，在窗格外松开以前不会结束拖选（`pressed` 一直留着），自动滚会停不下来。
- `view/glide.rs`：`pixels()` 去掉 `#[cfg(test)]`，自动滚要用它判断是否已经到底。

**验证了什么**
- 先红后绿（先写只返回“不动”的空实现，测试因此失败，实现后通过）：`view::edge` 7 条（上下方向、格子里不滚、越远越快有上限、按像素一直滚、按行滚、到顶到底停、回到格子里停、只在拖选且不在全屏程序时滚）；`view::press` 2 条（哪些按下算拖选、在窗格外松开／不按键移动／窗口失去前台都结束拖选）。`a_frame_after_a_long_pause_takes_no_leap` 在空实现下也通过（空实现本来就不动），实现后仍通过。
- 三项检查：`cargo test --all-targets` 875 过 0 失败；`cargo clippy --all-targets -- -D warnings` 无警告；`cargo fmt --check` 过。

**拿主意的地方**
- 速度：刚出边每秒 8 行，每离远一行每秒多 16 行，最快每秒 120 行（离边大约 7 行时到顶）。用户试过觉得快慢不合适再调这三个数。
- 判断“在边外”用窗格的边，不用最后一行格子的下沿：窗格底下不足一行的那条空白里不滚。
- 从 ⌘ 按住链接拖出来变成选区的（`LinkDrag`）也算拖选，一样会滚；⌘ 按在链接上还没拖开时不滚。
- 按住 ⇧ 在要了鼠标的程序里拖选，走的是普通选区，不在全屏时也会滚。

**没做的事**
- 报给程序的按下（`Reported`）在窗格外松开，`pressed` 仍然留着，这是原来就有的问题，不在本任务范围，没改。
- 滚轮、触控板、单击、双击、三击、⌘ 点链接的行为都没动。

**踩过的坑**
- 原来以为拖到窗格外时选区会贴着边那一行继续跟（任务文件「现在是怎样」也这么写）。实际上窗格只听得到自己上面的鼠标事件，拖到窗格外后选区就停在离开时的位置，松开也没人管。所以改成从窗口级事件里接住拖选。
