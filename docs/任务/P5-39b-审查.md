- **问题**：`confirming()` 检查整个 clears 表，不核对卡片是否仍在当前看板。用户点 Clear 后，如果任务文件在鼠标未移动时被外部删除，异步读取得到的新看板会移除卡片，但 accept／rebuild 不删除该文件的 Asking；读完成只清 Done。卡片不再绘制，也就不能继续依赖它的 on_hover(false) 或 Cancel 来清理这个条目。新增的全局 busy 判断会继续把它当成正在确认，后续 ctl 修改及等待落位的 start 可能一直被挡住。这是本次新增 gate 的直接可用性影响，不是未确认执行修改或错误完成结果，记建议改。
- **证据边界**：静态追踪了 clears 的写入／删除、新看板替换与 confirming 的调用；还核对了本机固定版本 GPUI 的 on_hover 注册方式（Apache-2.0 框架源码），没有把“元素被移除”当成有保证的离开回调。本项未做 GUI 重现，不能写成实测卡死。
- **改法**：换看板或接受新结果时清理已不存在卡片的 Asking，或者让 confirming 只统计当前仍可见、可操作的确认；保留真正显示中的确认对 ctl 的阻挡。补一个“确认中卡片被刷新移除后恢复可操作”的状态回归即可。
