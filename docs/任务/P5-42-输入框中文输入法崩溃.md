# 任务：输入框里用中文输入法时 paddock 崩溃

2026-10-08，paddock/main 自己做（`text_input.rs` 一处修复）。
类型：修 bug
依据：用户 10-08 09:07 的崩溃日志：主线程上系统拼音输入法（`com.apple.inputmethod.SCIM`）调 `setMarkedText`，经 `gpui_macos::window::set_marked_text` 进到 `TextInput::replace_and_mark_text_in_range` 后 panic；外层是 `extern "C"`，panic 不能展开，进程 abort。
提示：只修这一处，沿用现有写法。

## 在哪里干活
- worktree：`/Users/firegnu/Developer/personal_projs/paddock-worktrees/p5-42-ime-crash`，分支 `p5-42-ime-crash`（已从 main 建好）。

## 要做的
用户 10-08：“刚才崩了，这是崩溃日志。请帮忙查一下”；主控查明原因后用户说“写完就做”。

原因（主控照原逻辑写了一个小程序复现）：`replace_and_mark_text_in_range` 改自 GPUI `examples/input.rs`，算新选区时有两处错：结尾加的是 `range.end`，应为 `range.start`；输入法给的选区是相对拼写中文字的 UTF-16 位置，却按整个输入框内容换算。每打一个拼音字母，选区就落到文字末尾之后（光标前有中文时偏得更多）。选字上屏走 `replace`，会把选区重设对，所以平时看不出；输入法把拼写中文字清空（退格删光拼音、按 Shift 切中英文）后再打字，就拿越界的选区去切字符串，于是 panic。

做法：
- 把“替换并标记拼写中文字”的逻辑挪进 `EditState`，便于单元测试；新选区按拼写中文字内部的 UTF-16 位置换算，加上替换起点。
- 先写会失败的测试，覆盖：空输入框打拼音、删光、再打；已有文字时同样操作；光标前有中文时打拼音，选区落在拼写中文字里。
- 终端窗格的输入法（`ime.rs`）不切字符串，不动。
