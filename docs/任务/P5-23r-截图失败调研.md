## 要查的
用户原话：“派codex去调查一下，为什么paddock申请截屏和屏幕录像，总是失败，我已经把paddock加入macos系统的屏幕截屏和录制的可允许列表中了”

1. 截图失败时，系统到底拒绝的是谁：发起截图的是 `screencapture`，macOS 把屏幕录制权限算在哪个“负责进程”头上（agent 的 shell、codex/claude、corral 的进程、启动它的终端或 paddock.app、launchd 下的什么）。用系统日志（`log show`／`log stream`，TCC 相关的 subsystem）、进程树（`ps`）等只读办法拿证据。
2. 用户加进允许列表的 “paddock” 是哪一个、为什么没生效：ad-hoc 签名、每次打包 Identifier／cdhash 变化、`Info.plist` 没绑定、`cargo run` 的二进制和装好的 app 不是同一个，这些分别有没有影响，用证据说话。
3. 失败是不是根本不是权限问题：例如窗口编号不对、窗口被遮挡或不在屏幕上、`PADDOCK_NO_ACTIVATE` 带来的影响、macOS 27 上 `screencapture -l` 的行为变化。能区分就区分。
4. 给出能让 agent 截到自己窗口的办法，按推荐排：要用户在系统设置里做什么（具体授权给哪个程序）、paddock 打包或签名该怎么改（只写建议，不改）、或者改用别的截图方式（例如 paddock 自己把窗口画面存成图片）。每个办法写清代价和要不要用户点头。
