## 要做的
1. **只有左边一列是毛玻璃，从最上面到最下面**：左侧栏（展开时）或收起后的窄条，连同它正上方那段标题栏（红绿灯、收起图标、Agents、铃铛那一段），从窗口最上沿（红绿灯那一行）到最下沿，整列后面都是系统模糊，中间不夹不透明的横条。侧栏拖宽、收起展开、改字号、窗口缩放时，这一块跟着对齐，不留缝、不盖到右边。
2. **右边恢复原样**：标题栏右边（标签、`+`、分屏、搜索、右侧栏按钮及它们的高亮）、窗格卡片之间和四周的缝、终端、右侧栏、弹出框，都恢复成 P5-19a 之前的不透明样子。
3. **系统材质**：用 `NSVisualEffectView`，侧栏材质（`.sidebar`），透过窗口后面（`behindWindow`），保留系统的磨砂、提亮和饱和度，不像 GPUI 那样去掉。视图放在 GPUI 内容下面，只用来显示，不接鼠标键盘事件。材质的深浅外观跟主题走（三套主题都是深色就用深色外观）。窗口在后台时跟系统侧栏一样变淡，照系统默认。
4. **侧栏上的颜色**：侧栏这一块 GPUI 画的底色改成很淡的主题色罩（或不画），让磨砂透出来；卡片、选中、悬停、等你的琥珀底、小格、按钮底是半透明叠在上面，层次和文字仍清楚。三套主题各定数值，放在代码里，不新增配置项和 `[colors]` 键。P5-19a 加的、现在用不上的东西删掉。
5. **全屏退回不透明**：全屏时隐藏这个视图，窗口切回不透明，样子和 P5-19a 之前一样；退出全屏恢复。
6. **稳**：AppKit 调用都在主线程；视图的所有权清楚，窗口关闭、重开窗口不崩溃不泄漏；拿不到 `NSView` 或建视图失败时退回不透明，照常能用。

## 完成记录

- **做了什么**：
  - 新增 `app/src/frost.rs`：经 `raw_window_handle::HasWindowHandle` 拿到 GPUI 的 `NSView`，在它的父视图（窗口的 contentView）里、GPUI 视图下面插一个 `NSVisualEffectView`，从左边起、整高，高度随窗口自动伸缩。只在主线程建（`MainThreadMarker`，拿不到就不建）；`Frost` 持有它，丢弃时 `removeFromSuperview`。它被 GPUI 视图整个盖住，收不到鼠标和键盘。
  - `window.rs`：纯函数 `frost_column` 从“收起与否、全屏与否、侧栏宽度、窗口大小、界面字号”算出毛玻璃那一列：展开是侧栏宽，收起是窄条宽，都从顶到底；全屏没有。窗口建好时装视图，装上了才切 `Transparent`，侧栏改用磨砂取色；装不上就一直 `Opaque`，和 P5-19a 之前一样。全屏进出在 `observe_window_bounds` 里切 `Opaque`／`Transparent`。根元素有这一列时不再铺整片底，改画两块：列上一层很淡的 `agents_bg`，列右边整片不透明 `agents_bg`（标题栏右段、卡片之间和四周的缝都落在这上面）；没有这一列时照旧整片不透明。
  - 右边恢复：去掉 P5-19a 加在标题栏上的半透明（标签高亮、悬停底、×、`+`、分屏、搜索、右侧栏按钮），这部分代码回到 P5-19a 之前。`main.rs` 也回到 P5-19a 之前（窗口以默认的 `Opaque` 打开）。
  - `sidebar.rs`：P5-19a 的 `full_screen`、`card()` 和各处 `alpha` 换成 `frosted` 加 `Grounds`。不透明时（全屏，或装不上视图）取色和 P5-19a 之前逐一相同。磨砂时侧栏本身不画底：选中和点亮的按钮叠一层文字色，悬停取它一半，等你叠琥珀，窄条的短分隔线也用文字色。两层半透明叠加用新写的 `over()`，叠在不透明底上和 `Hsla::blend` 结果相同。

- **拿主意的地方**：
  - 材质与外观：`NSVisualEffectMaterial::Sidebar`、`BehindWindow`；`state` 不设，跟着窗口前后台走，在后台变淡照系统默认。系统的磨砂、提亮、饱和度都不动。外观按 `agents_bg` 的亮度选：小于 0.5 用 DarkAqua，否则 Aqua；三套主题都是 DarkAqua。
  - 视图宽度跟着那一列走。变宽时立刻放大；变窄时等 GPUI 下一帧画完再缩（`on_next_frame`）。原因：GPUI 的 Metal 画面不和 AppKit 的视图改动同步（`presents_with_transaction` 为 false），先缩视图的话，可能有一帧那一列里透出没模糊的桌面；先放大则多出来的部分压在旧画面的不透明底下，看不见。
  - 三套主题的数值（`wash` / `lit` / `waiting`）：dune 0.30 / 0.10 / 0.11，tide 0.34 / 0.12 / 0.12，lagoon 0.38 / 0.12 / 0.12。`wash` 只是把系统的深灰磨砂往主题色上带一点，主题越深、越饱和带得越多，好和右边接上。原来的选中色约等于在 `agents_bg` 上叠 6.5%（dune）到 8%（tide、lagoon）的文字色；磨砂底更亮、纹理更杂，所以按约 1.5 倍叠文字色。这样无论磨砂深浅，选中都比周围亮，悬停介于两者之间。如果把原来的颜色直接乘不透明度，在稍亮的磨砂上选中反而比周围暗。等你的琥珀从 0.07 提到 0.11～0.12。这些都是没在真窗口看过的估计，要用户看了再调。
  - 收起成窄条时，那一列就是窄条的宽度（默认 52），照“窄条连同它正上方那段标题栏”。标题栏左段（红绿灯加展开按钮）比窄条宽：默认字号下，交界线落在第二、第三个红绿灯之间（最小化按钮到 48，缩放按钮从 54 起），缩放按钮和展开按钮落在不透明底上；界面字号大时，交界线会穿过缩放按钮。展开按钮所以用不透明的悬停底。
  - 头像角上状态点的“圈”和窄条小格圆点的“圈”，原来靠卡片或窄条的底色假装挖空。磨砂时卡片底是半透明色或者没有，头像上的圈只能跟着半透明，窄条上的圈就没有了。
  - `Cargo.toml`：直接声明 `objc2-app-kit = "=0.3.2"`（`default-features = false`，features 是 `NSAppearance`、`NSGraphics`、`NSResponder`、`NSView`、`NSVisualEffectView`），锁文件里本来就有这一版。用不到 `objc2-foundation`、`objc2-core-foundation`，没声明。`button()` 的第一个参数改成“（主题，底色）”，免得参数超过 7 个。
