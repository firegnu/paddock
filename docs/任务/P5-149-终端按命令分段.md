## 要做的

### 一、让 shell 发标记
1. 用 OSC 133（`A` 提示符开始、`B` 命令开始、`C` 输出开始、`D;<退出码>` 命令结束）这套通行标记。
2. 普通 Shell 和 Agent shell 是 zsh、bash 时，paddock 注入集成脚本：zsh 照 Agent shell 的私有 ZDOTDIR 先读用户的 `.zshenv`、再照常读用户的其余配置；bash 照私有 rcfile 读 `.bashrc`。用 precmd／preexec（bash 用 PROMPT_COMMAND 和 DEBUG trap 一类的通行做法）发标记，不改用户的提示符外观，不改用户的任何文件。Agent shell 原有的替身目录优先等行为不变。
3. 用户自己已经装了别家集成（iTerm、VS Code 的脚本）也发 OSC 133 时，不要重复出两套标记。
4. 其他 shell（fish 等）不注入；它们自己发了 OSC 133 也照样认。agent 窗格不注入、不画这些标记。

### 二、终端层认标记
5. 终端层接 OSC 133（可以照 `Signals` 旁路解析 OSC 9;4 的办法），把每条命令的提示符行、输出起止、退出码钉在对应的行上：往上滚、历史被裁掉、清屏（`clear`、⌘K）、改窗格大小后，标记都要和文字对得上，对不上的丢掉而不是画错地方。全屏程序（备用屏，比如 vim、less）期间不记。
6. 守 §2 的边界：终端层不依赖侧栏、corral、看板、Settings；要和宿主来往走事件或传进去的参数。

### 三、画出来（照样稿）
7. 失败（退出码非 0）的命令：左边留白里一道 2px 细红线，从提示符行到输出最后一行；成功的不画。
8. 位置条（往回翻时出现的那根）：每条命令一道刻度，失败的用红色。
9. 鼠标停在一段命令旁边：整段淡淡托起，左边出现灰条，提示 `Click the bar to select output`（界面文字英文）。
10. ⌘↑／⌘↓：跳到上一条／下一条命令，让它贴着窗格顶；提示符行亮一下约半秒淡掉；位置条上它的刻度变长；到头了不动。系统“减弱动态效果”时不做淡出（直接到位、短暂高亮后消失即可）。
11. 点左边灰条：选中这条命令的输出（不带命令那一行），用现有选区的样子；⌘C、选中即复制、选区工具条照现有规则。
12. 颜色一律从主题取，深浅主题都要看得清。

**拿主意的地方**
- 没照样稿加 18px 的左边：红线和灰条画在现有 6px 留白里，窗格排版、和 agent 窗格的对齐都不变；代价是灰条能点的宽度只有 6px。要加宽只改一处，但所有 shell 窗格会少一两列，留给用户看过再定。
- 悬停：鼠标在命令的任一行上（含左右留白）就托起；只对已结束、有输出的命令（灰条只为选输出），打字、按下别处、离开窗格就收起，程序要了鼠标时不出。
- 提示符里的标记加 `;paddock=1`：iTerm 的标记和 paddock 的一字不差，不加记号分不出是不是别家。别家在场时 zsh 第一个提示符会带两套 A，终端层把重复的提示符合成一条，不会多出命令。
- 历史放宽 1024 行再裁回：解析器自己丢旧行时不告诉外面，只有这样行号才数得准；看得到的历史仍是 10000 行。
- 颜色：红线和失败刻度用界面的 `danger`；亮一下用 `focus` 的 22%（Latte 里 `focus` 是紫色，样稿画的是 lavender）；托起、灰条、刻度用终端前景色的不同透明度，深浅主题跟着变。
- ⌘↑ 从哪算起：视野还在上次跳的位置就从那条算，否则从视野顶行算；视野在最底下时到最近一条。命令就在屏幕里、视野挪不动时只亮那一行，再按继续往上。
- ⌘↑／⌘↓ 只绑在终端窗格，不进菜单（样稿没有）。
- `Segment` 加了一个滚动中不变的编号，用来记住悬停和跳到的是哪条；窗格换会话时清掉。

**没做的事**
- ⌘K：paddock 没有这个键，没加；`clear`（清屏加清历史）和 zsh 的 Ctrl+L（只清屏）发的序列测过，标记都对得上。
