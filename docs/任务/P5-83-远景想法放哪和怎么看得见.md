## 主控的建议（用户没逐条表态）

### 放在哪
- 一个不放代码的仓库，`~/Developer/personal_projs/<名字>`，和 paddock、ranch 平级；它是所有项目的上游，不挂在这套工具下面。
- 私有，只留本机，先不加远端：里面是没成形的想法。
- 名字主控提议 `pasture`（还没上工的先养着，和 ranch、corral、paddock 一套）。

### 想法怎么记
- 一个想法一份文件，开头一行状态：在想、准备立项、已立项（去了哪个仓库）、放下。
- 正文：要解决什么、为什么想做；还没想清的问题；查到的资料和别人的做法；到什么程度算可以立项。
- 可以在“在想”里停很久。
- 先不套看板的任务文件格式：排队、进行中、完成三栏对“还在想”的东西不合适。

### 立项怎么走
- 新项目：新开一个仓库和它自己的主控；第一份背景和设计文档起草后用户看过再放进去。
- 属于已有仓库的想法：写成需求，用户看过后交给那个仓库的主控。
- 谁来陪着想、谁起草：没有 P5-84 的那个 agent 时，就是用户自己，或在这个目录里开一个普通 agent。

### 会不会被分发（用户问：“所以所谓的家这个东西未来不会随着paddock或者cairn分发出去作为产品的一部分分发出去，对吧？”）
- 仓库里的内容永远是用户自己的，不属于任何产品。
- 只建仓库、定约定的话，paddock、cairn、ranch 的代码不用改，分发时不带任何和它有关的东西。
- 搭的时候把“约定和说明”和“用户的想法”放在不同的文件里，以后想把用法抽出来不用从内容里往外摘。

### 平时怎么看得见（用户指出的缺口：“但是是不是我只要不打开这个项目就没法知道现在家里面的任务。”）
用户说得对。右侧栏的 Kanban、Cairn、Changes 都跟着焦点窗格所在的目录走，不把焦点切到那个仓库里的窗格就看不到。所以：
- 只是存想法：paddock 不用改。
- 要随时看得见：paddock 要改，给它一个不跟焦点走的固定位置。主控建议的样子：
  - 左侧栏顶上固定一块，排在所有仓库组之上，里面没有 agent 开着时也在；一行概况（几个在想、几个准备立项）。
  - 点它，右侧栏列出里面的想法，不管当前焦点在哪个仓库。
  - 设置里加一项“这个目录在哪”，没填就不显示。
- 这样做的两个后果：
  1. 它成了 paddock 认识的一个概念，功能随 paddock 分发（别人填自己的目录也能用），内容仍只在用户本机。和上一条“不分发”的说法要一起看。
  2. paddock 要读得懂想法文件，文件就得有固定格式（标题、状态那一行），要和这个视图一起定，不能先随手写。

### 顺序
先定想法文件的格式、建仓库，用户可以马上往里记；paddock 里的固定位置作为单独一件活，先出样稿。

## 开工前要定
- 要不要照“一个私有仓库”这个办法做。
- 仓库的名字；谁来搭骨架（主控可以搭：建仓库、写约定、放想法模板、接上 cairn）。
- 想法文件的固定格式（状态有哪几种、开头几行怎么写）。
- paddock 里要不要固定位置；要的话是不是左侧栏顶上那个样子（先出样稿）。接受“功能随 paddock 分发”这个后果吗。
- 这件事要拆成两半：建仓库和定约定不是 paddock 的代码活；paddock 里的显示才是。拆开后各自怎么编号。

## 不做（现在）
- 不建仓库、不改 paddock、不出样稿：等用户定了上面几项。

## 10-11 续：paddock 要不要改
用户：“目录我同意你的，就是paddock要做修改吗？（这是我最纠结的，因为将来paddock分发的话，我害怕和这个家的概念捆绑到一块就麻烦了，但是我现在又不想每次都要打开这个repo才能知道我的未立项的想法）。”

主控改了两处先前的建议（用户还没表态）：
- **撤回“左侧栏顶上固定一个家”**：不往 paddock 里加“家”这个概念。
- **改成用现成的看板，想法照任务文件的格式写**（先前说“不套看板格式”）。读代码确认过：看板对任何有 `docs/任务/` 和 `main` 的 git 仓库都能用，能在看板上新建草稿、改优先级、点开编辑。所以：
  - 第一步，paddock 一行不改：想法仓库里建 `docs/任务/`，一个想法一份任务文件；在 paddock 里留一个开在那个目录的标签，点一下它，右侧栏看板就是想法列表，新建入口也在看板上（随手记）。
  - 对应关系：在想＝Queued（没提交的是 DRAFT）；更想做的标 `优先：高`，排在前面；已立项或放下＝用收尾提交挪进 DONE（放下的写「不做」，显示 Dropped）。In progress、To review、Merged 三栏空着。
  - 代价：界面上写的是 task、Queued 这些给开发任务用的词；文件名要带编号；首行是 `# 任务：`。
  - 第二步，只在“点一下标签”还嫌麻烦时做：给看板加一个通用的本事——不跟焦点走，可以切到别的仓库看。这对同时管几个仓库的人本来就有用，里面没有“家”的概念，分发时不存在捆绑。算一件单独的 paddock 活，先出样稿。

## 结论（2026-10-11 收）
用户 10-11：“P5-83我觉得其实已经完成了？”主控同意，两个问题都有了着落：

- **放在哪**：私有仓库 pasture（只在本机、没有远端），一个想法一份任务文件，放在它的 `docs/任务/`。约定写在 pasture 自己的 `AGENTS.md` 里，不在 paddock。
- **平时怎么看得见**：用 paddock 现成的看板看，paddock 一行没改。

- **没采用的**：在 paddock 左侧栏顶上固定一个“家”（用户怕分发时和这个概念捆在一起，已撤回）；想法文件另定一套不同于任务文件的格式。
- **留着的小缺口**：在看板上新建的想法是没提交的草稿，要有人在 pasture 里提交才变成 Queued。
