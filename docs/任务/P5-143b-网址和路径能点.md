### 做了什么
1. **认链接**（新文件 `app/src/view/links.rs`）：`links::at(term, point, files)` 只读鼠标所在那一处周围的格子（左右各最多 2048 格），跨自动换行折断的行（看行末格子的 `WRAPLINE`），宽字符的第二格当作它本身。依次认：
   - 程序用 OSC 8 标的链接（`Cell::hyperlink()`）：标同一个链接的连续格子算一整段（可以含空格）；`http(s)://` 当网址，`file://主机/路径` 当文件（`%XX` 解开，只在本机窗格认），别的协议（`mailto:` 等）不当链接、改按下面两种认。
   - 网址：`http://`、`https://` 开头，到空白、控制字符、`<>"{}|\^` 和反引号、全角标点（`，。、；：！？（）【】《》「」『』“”‘’⟨⟩`）为止；再去掉网址里没有配对的第一个 `)`／`]` 及其后面，最后去掉结尾的 `.,:;!?'*`。只有协议头不算。
   - 文件路径：在不含空白、引号、括号、`|,;=`、全角标点的一段里找；去掉结尾的 `.:!?`（`..`、`/.` 结尾保留）；可带 `:行` 或 `:行:列`。路径里要有 `/`（绝对、`~/`、`./`、`../`、`src/main.rs` 都算，`notes.txt` 不算）；相对路径按窗格的目录解析；**存在才算**（文件和文件夹都算）。前面带“词加冒号”的（`warning:src/main.rs:3`）也试冒号后面那段。远程窗格不认路径。
2. **窗格**（`app/src/view.rs`）：
   - 按住 ⌘ 移动鼠标（或在有键盘的窗格里按下／松开 ⌘，用 `on_modifiers_changed`）时找鼠标下的链接；有就整段（含折到下一行的部分）加下划线、指针变手（`CursorStyle::PointingHand`）。每画一帧都按当前鼠标位置重找一次，输出滚动、内容变了也跟着对。鼠标离开格子区域、松开 ⌘ 就恢复；没有键盘的窗格收不到 ⌘ 松开，画下一帧时看 `window.modifiers()` 清掉。
   - 按下的判断抽成 `start()`：⌘ 在链接上单击 → 记成 `Press::Link`，不选择、不报给程序；松开时发 `OpenLink(Target)` 事件。按住后拖到别的格子 → 从按下处开始普通选择（不打开）。不按 ⌘、或 ⌘ 不在链接上、或双击三击 → 和原来完全一样（程序要了鼠标就报，按 ⇧ 改选择，否则选择／选词／选行）。
   - 窗格的目录：shell 用开 shell 时的目录（不跟 `cd`），agent 用 agent 的 `cwd`，`Launch::Command` 用它的 `cwd`；开头的 `~` 展开成 `HOME`。
3. **打开**（`app/src/window.rs`、`window_ctl.rs`）：窗口订阅 `OpenLink`。网址走新抽出的 `PaddockWindow::browse(url, focus)`（就是原来 `Plan::Browse` 那几行，`Plan::Browse` 改成调它）：打开右侧栏、切到 Browser、`visit`；键盘留在终端（`focus = false`）。文件在后台跑 `links::opener` 给出的命令，`links::open` 用 `Command`（不经 shell）在 paddock 的 `PATH` 里找程序，等它结束；起不来或退出码非 0，侧栏底部出红色提示（`sidebar.note(…, true)`，和 paddock 别的出错一样）：`Couldn't open <路径>: couldn't run zedd: …` 或 `…: code exited with status 1: <它的 stderr>`。
4. **设置**（`config.rs`、`settings.rs`、`settings_view.rs`）：配置键 `open_files_with`（字符串，默认空），Settings › General › Terminal 一栏 “Open files with”，空时占位文字 “The app macOS picks”，下面小字 “For paths ⌘-clicked in a terminal; a command like zed or code -g goes to the line”；改了立即生效（`apply` 里更新）。空 → `open <路径>`；填了 → 按空白拆成程序和参数，后面接 `路径:行:列`／`路径:行`／`路径`。默认值为空的设置，Reset 链接改写成 “Reset to default”（原来会显示成 “Reset to ”）。

9. **`--wait`**：打开文件的整个过程（检查、启动、等待）在单独的线程（`paddock-open`）里跑，不占 GPUI 共用的后台执行线程；结果经 `async_channel` 交回界面。

### 做了什么

3. **stderr 读取线程会回收**（`links.rs` 的新 `Said`）：读取线程用 `libc::poll` 每次最多等 20 毫秒，有数据才 `read`，每轮看一次停止标记。`finish` 先 `wait` 直接子进程（`--wait` 时编辑器一直开着，这段时间照常读，不杀它），再等最多 200 毫秒读到结尾；到时还没结尾（留下的进程还拿着 stderr）就设停止标记并 `join` 读取线程，`finish` 返回时线程已退出、管道读端已关。
4. **查询线程起不来、通道异常结束时不再卡住**（`links.rs` 的 `Hover::start`、`Hover::lost`、`Spawn`、`thread`、`Look`；`view.rs` 的 `look_at_files`）：起线程改为 `Hover` 里可替换的 `Spawn`（正式用 `links::thread`，名字照旧 `paddock-links`）。起不来、或答案通道没给答案就关了：清掉在途标记，并记下鼠标还停在的那个候选（`lost`），同一候选不再立即重试；鼠标移到别的候选、移开再回来、松开 ⌘ 都会清掉这条记录，下次悬停重试。真正卡在磁盘调用里的查询没回来，在途标记照旧留着。

### 拿主意的地方
- 认 alias 用 `NSURLIsAliasFileKey`，没再加书签数据头的判断：`open` 认 alias 靠的也是这个标记（Finder 信息里的 alias 位），去掉标记的书签文件 `open` 也不会当 alias 跟过去。系统答不上来时按“拒”处理（宁可多拦一次），提示写明原因，用户可以在设置里填命令绕过。
- alias 检查放在扩展名检查之后、执行位检查之前，只对普通文件查（alias 本身总是普通文件；目录走原来的包判断）。
- 提示“看没看见”用“窗格被画出来”判断，不另加可见性状态：窗口只给当前标签页或放大的窗格调 `render`，这已经是看得见的唯一入口；整个窗口被完全挡住时 GPUI 也不画，提示同样留着。看过一眼又切走、5 秒后再回来，提示已过期，按要求只保证“显示后才开始计 5 秒”。
- “别每帧重试”的做法是记下失败时鼠标停着的候选，等鼠标离开它（换候选、离开格子、松开 ⌘）再放开，不用定时退避：重试只跟着用户的鼠标动作发生，次数有上限。答案通道关闭时若鼠标已经到了别的候选，只清在途标记，让新候选马上查。
- 读取线程每次 `poll` 最多等 20 毫秒：停止后最多 20 毫秒退出，`join` 不会久等；没用非阻塞描述符，因为只在 `poll` 说可读之后才 `read`，管道这时 `read` 不会阻塞。停止标记设下之后不再读，宽限期后才来的话不收（原来也只等 200 毫秒）。
