## 用户 10-20 已定的
- **谁来干**：loop 轮到下一件时，paddock 用 `corral send` 给这个仓库的主控送一句“开始做 <编号>”，由主控照它的规矩派活、审查、合并、收尾；paddock 不自己开开发 agent（用户 10-20：“甲，给主控送话”）。
- **哪些任务进 loop 要在看板上有交互**，要设计（用户 10-20：“我还要讨论kanban那边我如何定义哪些任务接下来进loop。这个交互要设计”）。样稿（claude.ai 上的“Paddock 看板 Loop 样稿”）上用户选 A（用户 10-20：“A”）：
  - Queued 上面单独一组 LOOP，组标题上有 Loop 开关和一行状态（开关、正在做哪件、后面还有几件）。
  - Queued 卡片悬停多一个 `Add to loop`（循环箭头），加到 loop 末尾；草稿没有这个按钮，等别的任务（`依赖：` 没做完）的按钮发灰、提示等哪件。
  - LOOP 里的卡片前面有序号，悬停有 `Move up`、`Move down`、`Remove from loop`；撤出后回到 Queued。
  - 开关打开、没有它送出的活在做时，把 LOOP 第一件送给主控，卡片进 IN PROGRESS 带 `Loop` 标记；收尾后送下一件，LOOP 空了自己关上。中途关掉，正在做的那件照常做完，只是不再送下一件。
- **撤出**：进了 loop 的任务，只要还没进行中，就可以从 loop 里撤出去（用户 10-20：“进了loop只要这个任务不再进行中，就可以从loop中撤出去”）。
- **“进了 loop”记在 paddock 自己那里**：按仓库各存一份，放在 paddock 的数据目录（和 Settings 一起），不提交 git；看板读时对一遍 git，已开工、做完、Drop、退回草稿的自动拿掉（用户 10-20：“同意，记在paddock里”）。
- **次序**：照 LOOP 里用户排的顺序，不再照 Queued 的高中低（样稿 A）。
- **loop 是外循环，不改主控的内循环**（用户 10-20：“不要改变现在的内循环的逻辑，这个loop我理解其实就是外循环”）：loop 只管“这件收尾了就送下一件”；主控照现在的规矩写任务、派活、审查、等用户实测和点头、合并、收尾，一件都不变，每件照旧停下来等用户确认再合并。
- **怎么算一件做完**：只认 git：main 上出现这件的收尾提交（DONE，含 `不做` 的 Dropped）。主控回复里的 DONE 不算。
- **在等用户**：任务文件有 `待用户：` 时 loop 显示 Needs you、等着，不跳去下一件。这靠主控照 CLAUDE.md 已有的规矩（等用户时写 `待用户：` 并提交），包括停下来等用户点头合并；不另加规矩。
- **送话的时机**：只在主控 idle、没人 attach 在它上面时送，不插进它正在做的事。
- **卡住怎么认**（用户 10-20：“同意，15分钟”）：这件送出后主控 idle 满 15 分钟（working 时不计）、既没收尾也没写 `待用户：`，算卡住，LOOP 标 Needs you、写 `Stuck: …`，收件箱提醒一条；paddock 不自己催。卡住时用户可以 `Nudge`（再送一句让主控接着做或说明卡在哪）、`Skip`（放回 Queued、做下一件）或关掉 Loop。
