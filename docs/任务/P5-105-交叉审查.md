1. **R1｜必须改：P5-93 的无变化回调仍会触发部分迁移存盘，丢掉尚在等 Git 的旧名字。**

   位置：`app/src/sidebar_workspaces.rs:187–206`、`:244–247`；`app/src/agents.rs:334–349`；`app/src/workspaces.rs:30–36`。

   问题：`named_read()` 的等待只在 `Sidebar::adopt_named` 入口检查，`join_started` 直接进入 `edit_workspaces`。后者在 `before` 快照之后、实际变更之前无条件执行 `Panel::adopt_named()`。例如旧名单有正在运行的 `a/main`、`b/main`，它们属于不同仓库；只读到 a 的仓库，b 的 cwd 还没有 Git 结果。这时自动迁移本应等待，但从 workspace 开的另一个 agent 若仓库已在别处，`join` 虽返回 `false`，a 的迁移已经使整个名单与 `before` 不同，于是仍然存盘；序列化又把 b 的名字写成空，之后读到 b 的仓库也无法补回归属。`join(None)` 或目标 workspace 已被删除时同样成立。部分已读、部分待读是可达状态：Git 正在收集旧 cwd 列表时，Corral 可以先报告新增或重启的旧名单 agent。

   改法：分开判断实际名单操作和自动迁移是否应当存盘；`join` 没有改变名单时，不得借由部分迁移绕过等待。自动迁移应对本次重读后的名单检查 `named_read()`，满足条件才落盘。补直接回归：两个旧名字一已读一待读，分别经过“仓库在别处”和“读不到仓库”的 P5-93 回调，待读名字不能从文件消失。这里要求保护的是**没有实际名单变更的回调**，不扩大为推翻已接受的显式改名单清理规则。
