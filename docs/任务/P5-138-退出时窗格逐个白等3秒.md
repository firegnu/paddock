## 现在知道的（主控 10-17 查的）
- 退出时 GPUI 先调 `on_app_quit` 的回调，再清掉窗口（`gpui-pre-0.3.8` `src/app.rs` `App::shutdown`：先 `quit_observers`，后 `windows.clear()`），窗口里的窗格随之在界面线程上依次 drop。
- `app/src/pty.rs` `impl Drop for Session`：先 `interrupt()`，再每 10 毫秒查一次直到子进程退出；`poll_exit` 在开始停之后 3 秒发 SIGKILL。所以一个不肯退的子进程要白等 3 秒，几个窗格依次各等 3 秒。
- `interrupt()` 对 shell 窗格给它的进程组发 SIGHUP；对不是 shell 的（agent 窗格里的 `corral attach`、远程 attach、`Launch::Command` 直接跑的命令）只给子进程发 SIGINT（这一行是 M0 从 Saddle 迁来时就有的）。
- 实测（主控自己开的 `paddock/test-quit2`，`-- /bin/sleep 3600`，用 `script` 给 `corral attach` 一个终端）：对 `corral attach` 发 SIGINT，5 秒后还活着；发 SIGHUP 立刻退出，agent 本身还在（`corral status` 照常）。
- 结论：开着 N 个 agent 窗格，⌘Q 后窗口已经消失，进程还要再活约 3N 秒，这段时间 Dock 显示它还在后台跑。实际用了多久没计时，是按代码推的。

### 做了什么

- 非 shell 的 `Session::interrupt` 改为向自己的 PTY 子进程发送 SIGHUP；shell 的进程组 SIGHUP 和 3 秒 SIGKILL 兜底保持原样。
- `on_app_quit` 在 GPUI 清窗口前收集所有 `PaddockWindow` 的 Session，覆盖全部标签页、当前及未显示机器的窗格，也覆盖 `Launch::Command` 的直接 Session。先逐个发信号、启动超时，再统一释放，由原来的 `Session::drop` 等待回收，避免每个窗格重新白等 3 秒。

### 验证了什么

所有 cargo 命令在 `app/` 下运行，使用任务指定的独立 `CARGO_TARGET_DIR`；命令均在前台跑完。

- 改信号前，`cargo test --lib pty::tests::dropping_a_command_that_ignores_sigint_hangs_up_promptly -- --nocapture` 确实失败：已装好忽略 SIGINT 的 trap 的非 shell Session，drop 用时 **3.012829791 秒**，违反小于 1 秒的断言。改 SIGHUP 后通过。

- 修复后 `cargo test --lib pty::tests:: -- --nocapture`：8 项通过，整组 **3.09 秒**。单个及多个只忽略 INT 的进程均小于 1 秒；3 个忽略 INT/HUP 的进程共等 3～5 秒，单个忽略 INT/HUP 的进程也在原定 3 秒后才结束；已退出进程不多等，shell 前台作业进程组被一起结束。
