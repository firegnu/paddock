## 现在知道的（主控 10-17 查的）
- 退出时 GPUI 先调 `on_app_quit` 的回调，再清掉窗口（`gpui-pre-0.3.8` `src/app.rs` `App::shutdown`：先 `quit_observers`，后 `windows.clear()`），窗口里的窗格随之在界面线程上依次 drop。
- `app/src/pty.rs` `impl Drop for Session`：先 `interrupt()`，再每 10 毫秒查一次直到子进程退出；`poll_exit` 在开始停之后 3 秒发 SIGKILL。所以一个不肯退的子进程要白等 3 秒，几个窗格依次各等 3 秒。
- `interrupt()` 对 shell 窗格给它的进程组发 SIGHUP；对不是 shell 的（agent 窗格里的 `corral attach`、远程 attach、`Launch::Command` 直接跑的命令）只给子进程发 SIGINT（这一行是 M0 从 Saddle 迁来时就有的）。
- 实测（主控自己开的 `paddock/test-quit2`，`-- /bin/sleep 3600`，用 `script` 给 `corral attach` 一个终端）：对 `corral attach` 发 SIGINT，5 秒后还活着；发 SIGHUP 立刻退出，agent 本身还在（`corral status` 照常）。
- 结论：开着 N 个 agent 窗格，⌘Q 后窗口已经消失，进程还要再活约 3N 秒，这段时间 Dock 显示它还在后台跑。实际用了多久没计时，是按代码推的。

## 要做的
1. 关窗格时不是 shell 的子进程改发 SIGHUP（关终端就是挂断），不再发 SIGINT；shell 窗格照旧给进程组发 SIGHUP。3 秒后 SIGKILL 的兜底留着。
2. 退出时先给所有窗口里所有窗格的子进程一起发信号，再让它们各自等退出，总共等的是最慢的那一个，而不是一个个加起来。放在 `on_app_quit` 里做（它在清窗口之前跑），这样 ⌘Q、程序坞菜单退出、注销都走到。
