# 任务：paddock 窗口不在焦点时，要看得出来

草稿（2026-10-20，paddock/main 记）。只记了用户的话，范围和验收还没定，开工前和用户过一遍。
依据：用户 10-20：“再加一个draft task，当焦点不在paddock窗口的时候，要能识别出来现在paddock不是当前的焦点。”

## 现在知道的（主控 10-20 对着代码看的，开工前再核对）
- 代码里已经有几处在看窗口是不是当前焦点（GPUI 的 `window.is_window_active()`、`observe_window_activation`）：
  - 终端窗格：`app/src/view.rs` 画的时候用 `focus.is_focused(window) && window.is_window_active()` 算“有键盘”；窗口失去焦点时取消正在按的鼠标操作。
  - 侧栏（`app/src/sidebar.rs`）和窗格标签的发光（`app/src/window.rs`）在窗口不活跃时不亮。
  - Settings（`app/src/settings_view.rs`）在窗口重新变活跃时刷新。
- 也就是说程序内部已经知道；用户觉得“识别不出来”，多半是界面上看不出来，或者某处行为没跟着变。具体是哪种，等用户说。

## 要和用户定的
1. “识别出来”指谁识别：用户一眼看出来（界面变化），还是 paddock 自己按焦点改行为（例如不在焦点时才发系统通知、提醒），还是两者都要？
2. 用户是在哪儿发现分不清的：终端光标、窗格边框、标题栏、侧栏，还是别的？有没有截图或具体场景（例如切到别的应用后以为还在 paddock 里打字）？
3. 要照着谁做：macOS 标准做法（标题栏和红绿灯变灰、选中色变灰）、Zed、Ghostty 等终端（光标变空心）？
