# 背景与决策记录

记录用户原话、作者（saddle/dev-claude-1）的建议和用户最终的决定。原话逐字照录；“建议”只是建议，不代表已批准。时间均为 2026 年。

## 1. 起点：Saddle 的 T76

T76 是 Saddle 待办里的“评估用 GPUI 将 Saddle 演进为独立桌面应用”。登记时用户原话：

> 现在的都是rust的tui库写的，是否可以用gpui来写？这样更加接近桌面。
> 这个记到一个新任务里，我理解如果这样的话，saddle这一套将会进化成一个桌面应用。不会再限制到terminal中了，对吧？

## 2. 详细调研（10-05）

用户原话：

> 把T76 gpui这个任务给他，让他详细研究下，给出详细的方案文档。

产出：`docs/调研/T76-GPUI桌面化详细方案.md`（Saddle 仓库原文的副本）。经 Saddle 主控两轮审查后作为讨论材料，**不代表架构获批**。

要点：
- GPUI 仍是 pre-1.0，官方 crates.io 版本停在 2025-10 的 0.2.2；实际可用渠道是固定官方仓库提交或第三方每周快照 `gpui-pre`。
- 显示与仿真可以沿用 Saddle 已用的 alacritty_terminal 和 portable-pty。
- 建议路线是“原生外壳＋字符面兼容层”，并保留 TUI 作为 SSH/手机入口。这些都是建议。

## 3. 方案提交后的讨论（10-05）

用户追问 GPUI 之外的路线后，明确了首要顾虑：

> 对，我担心的主要是terminal那边的集成，我需要接近原声terminal或者类似ghostty直接可以嵌入进去的

> 其实zed的终端我试过，是可以满足我的要求的

用户提供了 Zed 内置终端运行 Claude Code 的截图（在用户本机，未入库），作为体验参照。由此确定：终端以“GPUI＋alacritty_terminal 自己画、达到 Zed 内置终端的水平”为目标，暂不追完整嵌入 Ghostty。

关于 herdr-gpui（第三方 GPUI 版 Herdr 客户端），用户原话：

> herdr中文支持没问题，这个应该也没问题

作者的保留意见：herdr-gpui 的中文显示大概率没问题，但输入法要它自己在 GPUI 里实现，不能从 Herdr 推出来，未经验证。

## 4. 进入终端原型（10-05）

用户原话：

> 对，就是在一个独立的worktree上开发。不要污染主分支。你可以交代给dev-claude-1做了。

范围由 Saddle 主控定为“只做一个窗口和一个终端窗格，不迁移完整应用”。结果见 `docs/原型实测记录.md` 和 `docs/任务/T76-GPUI终端原型.md`。

## 5. 为什么独立成仓库（10-05）

用户先确认理解：

> 等一下啊，这个会一直在独立的worktree中开发吗？因为我还想保持现在saddle独立性，我理解插件等也是独立的，现在做的只是把saddle转为gpui，我这么理解对吗？

作者的回答要点：
- 插件、Corral、Drover 和界面无关，按设计不需要动。
- 建议的方向是“给 Saddle 加一个 GPUI 前端”，不是把 Saddle 转成 GPUI；TUI 保留。
- 真做桌面版时，Saddle 自己可能需要一些行为不变的调整（例如新输出通知），这些要用户同意。

用户随后表达担心：

> 我担心的就是合并这个做法，我担心两边会冲突

> 我觉得即使合并到主分支，也要隔离起来，不能两边互相影响。尤其是所使用的rust库。这个应该怎么做？还是说cairn做一个独立的repo

作者比较了“同一仓库内隔离”和“像 cairn 那样单独开仓库”，推荐后者。理由：
- 单独仓库按提交号引用 Saddle，Saddle 的改动在主动升级引用之前不会影响桌面。
- Saddle 仓库里不会出现任何 GPUI 代码、依赖或工具链要求。

用户决定：

> 单独开仓库吧，原型搬过去。该有的上下文也写到这个repo中。便于这个repo的主控能够快速接手。名字你考虑几个，我来挑一下

> 就用 paddock 吧

“保持 Saddle 独立性”的理解（作者的解读，用户没有逐字确认）：Saddle 及其 TUI 继续独立开发和使用；paddock 的工作不能以任何方式影响 Saddle，尤其是 Rust 依赖。paddock 需要 Saddle 改动时，走 Saddle 自己的流程，由用户同意。

## 6. 原型体验与主题（10-05）

用户在原型窗口里开 Claude Code，用中文输入法发消息，看了中英混排、表格、表情和代码块的显示（截图在用户本机，未入库）。用户原话：

> 对，我的建议是，起码有一套theme系统，就像saddle那样。

随后用户在三个选项中选定（均为作者推荐项）：

作者建议第一阶段范围：一个窗口、左侧 Agents 列表、右侧一个终端窗格，点哪个 agent 接哪个，也能开普通 shell；外加上面的主题系统；不做分屏、标签、插件页面、Drover、布局保存。用户原话：
